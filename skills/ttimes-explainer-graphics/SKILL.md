# 티타임즈 설명 그래픽

사용자가 지시하여 제작한 그래픽의 **설명 구조와 실제 시각적 결과**를 함께 참고한다. 화면구성 스킬은 언제 어떤 그래픽이 필요한지 선택하고, 이 스킬은 그 그래픽을 실제 이미지로 만든다. 문구·도형 목록이나 제작 프롬프트만 전달하고 이미지 제작이 끝났다고 하지 않는다.

## 시작할 때

1. 해당 발화와 앞뒤 맥락, 사용자 수정, 확정된 문구·자료를 읽는다. 그래픽 한 장으로 이해할 관계를 한 문장으로 정한다.
2. [강정수 그래픽 사례](references/kang-jeongsu-20261007.md)를 읽고 현재 과제와 가장 가까운 **실제 참고 이미지**를 열어 본다. 예전 모델명·서비스 구조를 사실 자료로 재사용하지 않는다.
3. 연도/분류 비교, 개념 축·임계선, 시스템 경계·흐름, 단계별 구성 중 발화를 설명하는 구조를 고른다. 모든 주제를 카드·화살표로 통일하지 않는다.
4. 기존 이미지 수정 요청이면 지정된 이미지를 기준으로 요청한 변경을 적용한다. 구조가 승인되어 색감·가독성만 바꾸는 경우 내용을 임의로 재설계하지 않는다.

## 구성 기준

- **설명 구조가 디자인보다 먼저다.** 무엇을 비교하는지, 어디에 무엇이 포함되는지, 화살표가 요청/전달/시간 중 무엇인지 정한다. 단순 나열을 인과관계처럼 연결하지 않는다.
- **용어를 눈에 보이는 대상으로 바꾼다.** 저장·연산·실행은 각각 SSD, GPU/HBM, CPU 같은 발화상의 구체적 대상으로 연결한다. 아이콘은 개념 식별에 쓰고 장식으로 채우지 않는다.
- **같은 비교축을 유지한다.** 연도별 비교는 연도 열과 분류 행을 고정한다. 누적 단계는 기존 요소의 위치·크기·색을 유지해 새 정보만 알아보게 한다.
- **큰 글자와 짧은 직접 라벨.** 제목/범주 → 대상 → 필요한 짧은 설명 순서로 위계를 준다. 긴 문단, 작은 각주, 포괄적인 슬로건을 추가해 화면을 채우지 않는다. 정확한 이해에 필요한 설명은 억지로 줄이지 않는다.
- **기본 시각 방향:** 밝은 배경, 진한 글자, 파랑 중심의 강조, 충분한 여백. 대비 대상은 주황 등 명확히 구별되는 색을 쓴다. 둥근 박스·옅은 음영은 정보 묶음에만 사용한다. 이 방향은 강정수 사례의 기본값이며 사용자 지정 스타일이 우선한다.
- **방송 화면에 맞는 비율.** 별도 지시가 없으면 16:9를 우선 검토한다. 넓은 구조도처럼 내용 때문에 다른 비율을 쓴 사례도 있으므로 모든 참조를 강제로 늘이거나 자르지 않는다. 말자막/설명자막과 병치되면 실제 표시 공간을 고려한다.
- **텍스트와 그림의 설명 역할을 분담한다.** 그림이 이미 말하는 내용을 제목·하단 슬로건으로 중복하지 않는다. 그래픽 라벨과 별도 설명자막은 구분한다.

## 실제 제작

AI 생성 이미지 또는 기존 래스터 이미지 편집은 사용 가능한 `imagegen` 스킬을 읽고 이미지 생성 도구로 제작한다. 선택한 참고 이미지를 실제 참조 입력으로 전달하고 유지할 구조와 바꿀 내용을 구체적으로 적는다. 기존 이미지 편집을 임의의 코드 재그리기로 바꾸지 않는다. 사용자가 편집 가능한 도형/벡터를 명시적으로 요청하면 그 형식에 맞는 제작 도구를 사용한다. 생성 PNG를 레이어가 있는 원본이라고 부르지 않는다.

제작 입력에는 필요한 항목만 포함한다:

- 전달할 한 가지 관계와 해당 발화
- 승인된 정확한 문구, 라벨, 비교축
- 실제 참조 이미지와 유지할 특징
- 객체, 포함 관계, 연결 방향, 의미 있는 강조
- 비율과 사용할 화면 공간
- 동시 완성형인지, 발화에 맞춘 단계형인지

모델명·연도·수치·로고·제품 구조는 제공된 근거와 대조한다. 추가 사실이 필요하면 공식 근거를 확인하며, 생성 이미지 자체를 사실 근거로 사용하지 않는다. 개념 그래프에는 실제 측정치처럼 보이는 임의 눈금·수치를 추가하지 않는다.

## 발화에 맞춘 단계형 그래픽

화면구성에 순차 지시가 있으면 완성 이미지와 함께 **무엇이 언제 추가/변경되는지** 짧게 남긴다. 예: 저장 SSD → ‘연산’에서 GPU/HBM 추가 → ‘실행’에서 CPU 추가 → VM 설명까지 유지. 줄바꿈만으로 애니메이션을 추정하지 않는다.

실제 단계별 파일을 요청받았거나 편집에 필요한 경우 같은 기준 프레임에서 파생해 기존 요소가 흔들리지 않게 만든다. 요청이 정지 참고 이미지 한 장이면 불필요한 전 단계 파일을 양산하지 않는다. 편집자의 재량인 전환 효과·세부 좌표는 고정하지 않는다.

## 검수와 전달

이미지를 직접 열고 한글 오탈자, 누락/중복, 로고·대상 대응, 축·교차점·화살표, 경계/포함 관계, 잘림·겹침을 확인한다. 실제 표시 크기로 축소해 주요 라벨이 읽히는지도 확인한다. 구조적 의미를 바꾸는 문제는 수정 후 다시 확인한다.

사용자 프로젝트 폴더에 결과를 저장하고 클릭 가능한 파일로 제공한다. `(그래픽 참고)`는 재제작/편집용 참고 상태를 뜻하며 자동으로 방송 최종 승인되지 않는다. 원본은 보존하고 수정본을 구분한다. 검수는 `pass`, 미확인은 `unverified`, 새 제작을 안 했으면 `not_run`으로 보고한다.

## 후속 학습

사용자가 고른 수정본을 기준으로 이전 결과 → 수정 지시 → 최종 이미지 → 발화상의 역할을 연결해 사례를 누적한다. 문구/구조의 수정과 디자인 수정을 나눠 기록한다. 실제 생성 프롬프트가 없으면 복원했다고 주장하지 않는다. 한 이미지의 색상·로고 개수·둥근 모서리를 모든 작업의 의무로 승격하지 않는다.
