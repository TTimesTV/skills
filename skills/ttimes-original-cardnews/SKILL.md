# TTimes Original Card News

**제작 전 필수:** `references/morning-news-vs-afternoon-youtube.md`를 읽고 오전 뉴스형 / 오후 유튜브 요약형을 먼저 구분한다. 오후 인터뷰는 1:1 리스트 풀사진 표지와 출연자 인용 마무리를 유지하며, 오전 카드의 본문 느낌·색감 참고를 전체 템플릿 변경으로 확대하지 않는다.

새 뉴스·정책·현상을 직접 발제해 독자가 판단할 수 있는 카드뉴스로 만든다. 영상·인터뷰 재가공용 `ttimes-cardnews-imagegen`의 승인된 상하 분할 템플릿과 별개다. 이번 형식의 거절을 영상 재가공 템플릿의 거절로 확대하지 않는다.

**최근 제작 규칙 필수:** `references/20260907-approved-production-rules.md`를 읽는다. 팩트체크만 요청하면 톤을 수정하지 않으며, 잠긴 카드의 부분수정은 요청 요소에 한정한다. 제목의 억지 줄바꿈·게시 지면의 작업용 표기를 금지한다.

## When to use

- 새 이슈를 취재·검증하여 카드뉴스로 만들 때
- ‘금지했다/출시했다’에서 끝내지 말고 연구·반론·시사점까지 요구할 때
- 링크드인용 문서 캐러셀, 사진·데이터 중심 새 편집 디자인을 만들 때

영상 원고·출연자 발언을 카드로 재가공하는 요청은 기존 영상 카드 스킬을 사용한다. 출연자 인용 마무리를 새 발제형의 기본값으로 강요하지 않는다.

## 권한과 완료 상태

사용자가 포맷을 맡기고 실제 결과물을 요구하면 내부 구성·검증을 거쳐 완성 후보까지 제작한다. 승인 요청만 남기고 중단하지 않는다. 반대로 원고·특정 페이지가 잠겼다면 그 범위를 바꾸지 않는다.

`RENDERED_CANDIDATE`, `USER_APPROVED_TEMPLATE`, `PUBLISHED`는 별개다. 이번에 새 디자인을 만들어 납품했다고 승인 템플릿으로 등록하지 않는다. 업로드는 따로 요청받기 전 실행하지 않는다.

현재 사용자 출력 선호는 **PDF 제외**, 개별 이미지와 요청한 GIF 표지다. `references/20260906-paper-motion.md`의 종이 질감·사진 반/글 반·고정 제목/움직이는 사진 기준을 우선한다. 아래 이전 PDF 렌더 계약은 사용자가 다시 PDF를 요청한 경우에만 적용한다.

## 1. 발제의 질문부터 고정

뉴스 사건 자체와 독자가 판단할 질문을 분리한다.

예: ‘뉴욕의 학생 대상 생성형 AI 유예’ → ‘AI와 낸 성과가 학생에게 남는 학습인가?’

권장 논리: 사건 → 정확한 범위 → 핵심 증거 → 다른 결과/반론 → 연구가 말하지 못하는 것 → 판단 기준 → 독자 질문. 페이지 수는 독립 논점에 따라 결정하며, 항상 9장이나 찬반 반반으로 강제하지 않는다.

## 2. 취재·팩트 검증

- 정책은 공식 원문에서 관할·대상·기간·예외·금지하는 실제 기능을 확인한다.
- 교육·건강·성과 주장은 원논문을 확인한다. 대상, 장소, 표본, 과목, 실험 조건, 비교군, 평가 시점, 단기/장기를 기록한다.
- %와 %p, 상대 변화와 절대 점수, 과제 수행과 학습 향상, 무효과와 효과 없음의 확정을 구분한다.
- 반대 결과가 있는 연구도 같은 수준으로 검증한다. 다른 연령·도구·과목의 결과를 같은 모집단의 직접 반박으로 취급하지 않는다.
- 연구 결과에서 도출한 제안·직장 등 다른 영역으로의 확장은 편집적 해석이라고 명시한다.
- 출처는 해당 카드에 짧게, 전체 URL·DOI·조건은 별도 출처표에 남긴다.

## 3. 사진은 증거와 식별용 자산

실제 인물·현장에 생성 이미지를 보도사진처럼 사용하지 않는다. 촬영자·통신사·날짜·상황은 내부 레저에 기록한다. 게시 지면에는 ‘자료사진 · 사용자 제공’ 같은 작업용 표기를 자동 삽입하지 않는다. 자료사진을 새 사건 현장으로 오인시키지 말고, 설명이 꼭 필요하면 사용자와 확정하거나 적절한 자산으로 교체한다.

사용자가 AFP 이용 권한을 말한 경우 그 진술과 이미지별 출처를 기록한다. 출처 표기만으로 이용허락을 획득한 것은 아니다. 로그인 벽은 중단하고 로그인/사진 전달을 요청한다. 공개 기사 이미지로 대체하면 포털 원본을 다운로드한 것처럼 말하지 않고 취득 경로와 권리 확인 범위를 남긴다. 워터마크 제거·접근 제한 우회는 하지 않는다.

## 4. 새 발제형의 디자인 판단

‘스타일 이름+벤토 박스’ 선택으로 끝내지 않는다. 표지·증거·비교·결론의 독자 과제에 맞춰 페이지마다 구조를 선택한다.

- 표지: 실제 인물/장면과 큰 질문. 인물의 정체·사건 범위를 작은 문구로 보완.
- 정책/범위: 필요한 대상만 구분한 행, 예외는 가독성 있는 보조 문구.
- 수치 반전: 단위·기준이 붙은 대형 숫자. 다른 평가 지표를 하나의 연속 꺾은선으로 만들지 않는다.
- 메커니즘: 서로 다른 작동을 비교. 같은 뜻을 제목·그림·본문에서 세 번 반복하지 않는다.
- 반대 증거: 시각적 리듬을 전환하되 같은 타이포·여백 시스템을 유지.
- 한계: 면책문을 쌓기보다 결과를 일반화할 수 없는 경계를 읽기 쉽게 표시.
- 결론: 독자에게 쓸모 있는 판단 기준. 연구의 직접 결론과 편집적 제안을 분리.
- 마지막: 링크드인 독자가 경험·조건·판단을 말할 수 있는 질문. 유도성 찬반이나 유일한 대안처럼 보이는 선택지를 피한다.

한글은 결정적으로 조판한다. 사진·정확한 데이터만 필요한 페이지에 생성 일러스트를 억지로 끼우지 않는다. 개념 일러스트가 필요하면 이미지 생성/디자인 도구를 별도 사용하고 보도사진과 명확히 분리한다.

## 5. 실행 가능한 초기 렌더러

초기 `original-editorial-4x5-v1`의 종이색/녹색/대형 숫자 중심 9장 디자인은 2026-09-06 사용자에게 **REJECTED_DESIGN** 판정을 받았다. 기본 스타일로 재사용하지 않는다. 코드는 조판 실험용으로만 보존한다. 새 제작 전 `references/20260906-photo-led-revision.md`의 실제 사진 중심 구성·짧은 기사체·장수 축소 피드백을 읽는다. 후속 4장 재시안도 아직 승인 템플릿은 아니다.

번들 렌더러는 macOS Apple SD Gothic Neo와 Avenir Next, Python Pillow를 사용한다. JSON을 읽어 PNG·PDF·접촉시트·텍스트 경계 기록을 만든다. 사진·로고 경로는 JSON 위치 기준 상대경로다. `references/renderer-contract.md`를 확인한다.

```bash
python scripts/render_editorial_cards.py /absolute/path/cards.json /absolute/path/new_output
```

작업 환경의 Pillow가 있는 Python을 먼저 확인한다. 예시 에피소드 경로는 계약 문서에 기록돼 있다. 한 장이 넘치면 본문을 무단 축소·삭제하지 말고 문구나 배치를 수정한 뒤 다시 검수한다. 폰트 파일을 납품 패키지에 복제하지 않는다.

## 6. 실제 검수와 납품

- 모든 장의 파일 수·순서·해상도·PDF 페이지 수를 코드로 검증.
- 텍스트 경계 밖 노출과 충돌 후보를 검사하고 실제 이미지를 시각 검토.
- 휴대폰 축소 화면에서 제목·핵심 숫자·본문 계층을 점검.
- 잘못된 출처, 빠진 연구 조건, 과장된 제목, 반복 논점, 사진 오인 가능성을 재검토.
- 수정 후 최종 파일의 해시를 새로 기록하고 이전 시안과 구분.
- 사용자에게 개별 이미지와 요청한 GIF·게시글을 전달한다. PDF·PNG 묶음은 요청 때만 제공하고 내부 출처 레저는 게시 지면과 분리한다. 내부 원고만으로 ‘완료’라 하지 않는다.
- 검사 통과는 결과물의 기술·내용 검수 상태다. ‘사람들이 감탄한다’거나 독자 반응이 검증됐다고 주장하지 않는다.

## 유지할 경계

기존 영상 재가공 승인 레이아웃은 그대로 유지한다. 새 발제형 디자인은 사용자 피드백을 받은 뒤에만 기본 형식으로 승격한다. 자동 평가표나 출처표가 실제 디자인 검토를 대신하지 못한다.
