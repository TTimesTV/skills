# 생성 경로와 프롬프트

## 입력 모드별 선택

| 모드 | 적합한 상황 | 확인할 한계 |
|---|---|---|
| Text to video | 장소 배치가 엄격하지 않은 새 장면 | 실존 도시 지리를 글만으로 고정하기 어려움 |
| Image to video | 시작 구도와 외형이 중요 | 이미지에 없는 뒤쪽/이동 경로는 생성됨 |
| First + last frame | 도착 구도까지 중요 | 두 프레임 사이의 경로·기하·속도는 별도 검증 |
| Motion reference | 특정 이동 리듬/궤적을 전달 | 실제 지원과 다른 입력의 동시 사용 여부 확인 |
| Video edit / retake | 원본의 특정 요소/구간 수정 | 이미지 참조·구간 선택·보존 수준은 모드별로 다름 |
| Extension | 기존 영상 다음으로 이어짐 | 기존 끝부분을 수정하는 기능과 다름 |

참고 이미지 업로드와 마지막 프레임 슬롯은 같은 기능이 아니다. 텍스트에 `IMAGE1`이라고 적는 것만으로 마지막 프레임 조건이 생기지 않는다. 입력 슬롯과 대응 관계를 설명한다.

## 끝부분만 바꿀 때

1. 원본을 보존하고 실제로 수정할 타임코드를 정한다. 아직 잘못된 공간이 나타나기 전의 마지막 정상 프레임을 후보로 고른다.
2. 원하는 끝 프레임을 준비한다. 시작과 끝이 같은 시간대·렌즈 성격·높이·진행 방향으로 연결 가능한지 점검한다. 정면과 후면이 뒤집힌 프레임이면 먼저 수정한다.
3. 지원되는 경우 이 두 프레임으로 필요한 뒷구간만 생성한다. 지원되지 않으면 시작 이미지 기반 짧은 샷 등 가능한 경로를 명확히 제시한다. UI 확인 없이 끝 프레임 기능이 있다고 가정하지 않는다.
4. 앞부분을 정확히 보존해야 하면 원본 앞부분과 새 뒷부분을 편집에서 연결한다. 전체 재생성에 `앞부분 그대로`라고 쓰는 것은 픽셀 보존 수단이 아니다.
5. 경계 프레임이 같아도 이동 속도·방향·노출 차이로 튈 수 있으므로 전체 재생을 확인한다. 속도 조절은 연속성을 다듬는 수단이며 잘못된 건물 방향을 고치는 수단이 아니다.

끝 프레임이 너무 멀거나 크게 회전되어 있으면 중간 프레임/샷을 추가한다. 원테이크가 필수라면 그 조건을 유지하면서 더 짧은 이동을 검토한다. 사용자 몰래 컷을 넣지 않는다.

## 두 층으로 작성

**연출 설계서**는 상세하게: 구간별 시작/끝 위치, 시선, 이동, 화면 속 변화와 성공 기준을 쓴다. 초 단위는 목표이고 모델의 프레임 단위 실행 명령이 아니다.

**실행 프롬프트**는 해당 모델에 맞춘다. 이미지 기반이면 이미 보이는 외형을 장황하게 재묘사하기보다 필요한 움직임과 최종 관계를 우선한다. 긴 프롬프트를 지원하는 모델이나 복합 연출은 필요한 내용을 유지한다. Runway Gen-4의 긍정문 권장을 다른 모든 모델의 부정문 금지로 일반화하지 않는다. `preserve everything`과 `rebuild the whole city` 같은 충돌은 작성 단계에서 제거한다.

### 영어 실행문 골격: 이미지 기반 단일 접근

아래 대괄호는 모두 실제 설계값으로 대체한다. 지원하지 않는 끝 프레임 문장은 삭제한다.

> A continuous aerial shot beginning from the supplied start frame. The camera travels [direction and path] at [pace], while looking [viewing direction and downward angle]. [Landmark] gradually enters [screen region]. The camera [one main movement], with [necessary supporting movement]. During the final [duration], it eases into [final camera position and framing]. From this viewpoint, [visible building face and near-to-far spatial relationships]. The final composition matches the supplied end frame. Maintain coherent perspective, natural parallax, consistent daylight, and stable architectural geometry throughout the move.

### 상세 타이밍 골격

- 0–A초: 출발 구도와 이동을 확립. 대상이 어디에 얼마나 보이는지.
- A–B초: 같은 이동을 이어 접근. 무엇이 가려지거나 드러나는지.
- B–끝: 감속과 마지막 구도. 허용되는 시선 조정만 지정.

8초 영상에 복잡한 전 구간 지리 재현과 여러 카메라 연출을 모두 넣지 않는다. 시간 구획은 동일한 움직임의 진행을 설명하는 데 우선 사용한다.

## 실패 분류와 다음 조치

| 관찰 | 우선 점검 | 다음 한 가지 변화 |
|---|---|---|
| 끝 화면이 거의 안 바뀜 | 실제 편집 모드와 이미지/끝 프레임 조건 적용 여부 | 지원 입력을 바꾸거나 뒷구간을 별도 생성 |
| 건물이 회전/변형됨 | 카메라 방향과 건물 방향 지시의 혼동, 기준 이미지 | 올바른 시점의 정지 이미지를 먼저 확보 |
| 앞부분까지 달라짐 | 전체 재생성 중인지 | 원본 앞부분을 편집에서 보존 |
| 중간 경로가 만들어짐 | 양 끝 사이 거리/시선 변화 | 중간 프레임 또는 더 짧은 구간 |
| 이동 대신 줌이 됨 | 동작 용어와 시차 설명 | dolly/truck 등 위치 이동을 명시 |
| 접합 순간 튐 | 속도·고도·시선·노출 불일치 | 경계 조건을 맞춰 뒷샷 수정 |

각 시도는 입력/모델/프롬프트 변경점/관찰/다음 조치를 짧게 남긴다. 실패 추정과 검증된 원인을 구분한다. 비용이 드는 생성은 사용자 요청 범위와 예산에 따르며, 리서치나 스킬 설치만 요청받았을 때 실험 생성을 자동 실행하지 않는다.
