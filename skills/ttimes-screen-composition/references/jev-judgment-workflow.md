# JEV 판단 보조

사용자 지시(2026-09-30): env에 있는 JEV를 판단 AI로 사용해 토큰 비용을 줄인다.

## 실행

- 영구 env: `JEV_ENV_FILE`, 키 이름 `TYPESAFE_API_KEY`. 키를 출력·복사하지 않는다. 작업 폴더에는 요청/응답만 보관한다.
- 기존 장치 연동: `https://api.typesafe.ai/v1/systemone`, `jev-1.13.0`. 서비스 사양 변경 시 실패를 보고하고 확인한다. 다른 모델로 조용히 전환하지 않는다.
- 실행기: `python scripts/jev_judge.py --input requests.json --output-dir <work>/jev`. 입력은 `{model,state,questions}` 객체의 배열이다. choice 질문은 `type`, `instructions`, `criteria`를 사용한다. noul은 yes/no 판단용이다.
- 실제 endpoint·모델·요청 내용의 SHA-256별 캐시. 성공 결과만 재사용하며, 불완전한 답변은 실패로 처리한다. 인증·잔액·모델 오류는 즉시 중단, 429/일시적 서버 오류만 최대 3회 시도한다. 오류 본문/키를 로그에 출력하지 않는다.

## 새 화면 구성

1. 메인 PD가 전체 회차와 연속편 맥락을 먼저 읽고 주체·행동·비교축·조건을 해석한다. 그다음 원고를 의미 단위로 나누고 원문 문단/문자 위치를 보존한다. 짧은 추임새는 앞뒤 맥락으로 남기되 불필요한 판단 질문을 만들지 않는다. 역할 분담은 `pd-led-research-review-workflow-20261014.md`를 따른다.
2. 8~12개 단위와 앞뒤 맥락을 한 번에 보낸다. 공통 기준은 state에 한 번 적는다. 기본 질문은 `화자 유지/강조/설명/구조/실자료/질문` 중 주 기능과 `추가 사실확인 필요` 두 가지로 충분하다. 불필요한 반복 장문 질문을 줄인다.
3. 전체 흐름을 읽은 제작자가 JEV 결과를 검토하고 화면 목적을 정한 뒤 실제 문구·자료·진입/종료를 결정한다. 불확실하거나 의미를 크게 바꾸는 판단은 직접 검토한다. 필요한 경우 정의 필요성, 비교/과정/수치, 중복, 과잉 단정을 명시적 기준으로 질문하되 매번 모든 질문을 추가하지 않는다. 자료 수를 채우지 않는다. NONE/화자 유지도 완전한 결정이다.
4. 실제 자료를 열어 확인한다. 연구 결과/계획/개인 경험을 구분하고, 검토 대상 주장의 사실성은 외부 근거로 확인한다. JEV 판단을 근거 출처로 쓰지 않는다.
5. 필요하면 의미를 강하게 바꾼 후보만 JEV에 2차 검토한다. 무조건 전량 재호출하지 않는다.

## 제1차본과 최종본 비교

- 실제 assistant 제1차 Word 제안과 사용자 승인 JSON을 같은 발화 기준으로 대응시킨다. 애매한 대응은 미확정으로 남긴다.
- 짝지어진 제안만 `유지/문구 수정/핵심 전환/자료 교체/삭제/추가/대응 불명`으로 JEV 1차 분류한다. 최종 영상은 별도 픽셀·오디오 관찰 근거이며, JSON 문구만으로 영상 구성의 부재를 추정하지 않는다.
- 주요 변경과 JEV 불확실 항목을 직접 검토한다. 반복되는 선택과 명시적 사용자 수정만 스킬 규칙으로 승격하고 단일 사례는 사례로 남긴다.
- 2026-10-07 강정수 비교에서 서로 다른 변화가 자료 중심으로 뭉뚱그려지는 경향을 확인했다. 문구 유지/수정과 화면 기능·자료·앵커·전개 변경을 별도로 검토하고, 원문 컷을 자막 거절로 분류하지 않는다. 필요한 기준과 대표 사례만 [강정수 참고서](kang-jeongsu-final-selection-20261007.md)에서 state에 반영한다. 새 비교 없이 승인된 분석을 스킬 문서에 반영하는 작업에는 JEV를 재호출하지 않는다.

## 완료 보고

호출/캐시 재사용 횟수, 반환된 사용량, 수동 검토 범위, 실패/미확인 항목을 기록한다. 비교 기준이 없으면 토큰 절감률을 말하지 않는다. JEV 실패 시 사용했다고 주장하지 말고 실패 원인과 수동 처리 범위를 구분한다.
