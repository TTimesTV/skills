# 박영선–박남규 자료 03 폭우 분석 사례

번호 자료의 배치 의도를 역추적할 때 쓰는 보정 사례다. 특정 프로젝트의 결론을 다른 프로젝트에 그대로 복사하지 말고, **인접 번호와 발언의 병렬 구조를 함께 읽는 방법**만 재사용한다.

## 패키지와 확인 사실

- 패키지 유형: 분리형 작업 패키지
- 자산: `03. (폭우)_AFP.mp4`
- 실제 미디어: 61.096초, 1920×1080, AFP 계열 영상
- 화면 내용: 강한 비, 우산을 쓴 보행자, 뭄바이 도로의 얕은 침수, 차량·버스·오토바이가 물을 튀기며 이동하는 장면
- 초반 일부 프레임: `MUMBAI / INDIA` 오버레이
- DOCX/말자막에는 `//03`이나 별도 `//자막` 배치 지시가 확인되지 않음

## 배치 추론

원고의 병렬 발언:

```text
기후 변화에 대한 염려가 많은데
홍수라든지
아니면 온도가 많이 올라간다든지
이런 기후 변화의 원인은 이산화탄소 배출이 많기 때문
```

인접 자산:

```text
03 폭우 AFP
04 폭염 Pexels
05 화력발전소 Pexels
```

따라서 다음 대응은 강한 추론이다.

- 03 → `홍수라든지`
- 04 → `온도가 많이 올라간다든지`
- 05 → `이산화탄소 배출이 많기 때문`

핵심은 첫 번째 일치 명사를 찾는 것이 아니라, **발언의 병렬 항목 수·순서와 인접 자산의 항목 수·순서가 맞는지 검증하는 것**이다.

## 기능과 선택 이유

- 주기능: `ILLUSTRATE` — 기후변화 우려의 사례인 홍수·침수를 즉시 시각화
- 부기능: 원맨 인터뷰 도입부의 리듬 전환
- `PROVE` 아님: 해당 뭄바이 강우가 기후변화나 CO₂ 때문에 발생했다는 인과를 영상이 입증하지 않음
- AFP 선택 이유는 실제 재난 현장성, 다양한 사용 가능 쇼트, 지역·출처 추적성이라는 실무적 동기로 보는 것이 안전함
- 특정 통신사 선택에 상징적 의미를 부여하거나 권리 허가까지 추정하면 안 됨

## 화면구성 판단

별도 편집자막의 근거가 없으므로 가장 안전한 판정은:

```text
자료 + 말자막
```

정확한 소스 타임은 미확정이다. 차량이 침수 도로를 통과하며 물을 튀기는 쇼트는 짧은 발언 안에서도 의미가 빨리 읽히지만, 이것을 실제 PD 선택으로 단정하지 않는다.

## 위험과 일반화 규칙

1. **지역 오버레이 위험:** 원고가 뭄바이를 말하지 않으면 `MUMBAI / INDIA`가 보이는 구간은 불필요한 사건 특정이 된다.
2. **강도 과장 위험:** 실제 화면은 폭우와 통행 가능한 수준의 도로 침수다. `대홍수`, `재난 현장`처럼 강도를 올려 쓰지 않는다.
3. **인과 오독 위험:** 예시 인서트를 기후변화의 직접 증거처럼 쓰지 않는다.
4. **파일명 축약 위험:** 파일명이 `폭우`여도 실제 픽셀은 폭우와 도로 침수를 함께 보여준다. 기능은 픽셀 기준으로 판정한다.
5. **병렬 순서 단서:** 짧은 병렬 발언과 연속 번호 자산이 1:1로 대응하면 강한 배치 증거가 된다. 단, DOCX의 명시 지시보다 우선하지 않는다.

## macOS File Provider 자료 확인 메모

OneDrive 등 File Provider의 온라인 전용 파일은 논리적 크기가 보여도 `dataless`이고 실제 블록이 0일 수 있다. 이 상태에서 해시가 빈 파일의 SHA-256처럼 나오거나 미디어 도구가 읽기 오류를 낼 수 있다.

검증 순서:

1. `stat`의 flags/blocks로 실제 바이트 상주 여부 확인
2. 필요하면 Finder/Open 동작 등 비파괴적 materialization을 유도
3. blocks가 0보다 큰지 재확인
4. 그 뒤 해시와 `ffprobe` 실행
5. 해시가 `e3b0c442...`인데 논리적 크기가 0이 아니면 정상 해시로 믿지 말고 hydration 상태부터 재검사

환경별 materialization 방식은 달라질 수 있으므로 특정 명령 하나를 영구 규칙으로 고정하지 않는다.
