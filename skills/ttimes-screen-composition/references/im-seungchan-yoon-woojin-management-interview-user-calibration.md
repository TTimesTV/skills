5. 관계를 이해하는 데 정말 필요한 경우에만 그래픽을 제안한다.

## 사용자 정본의 우선 문법

### 1. 기본 화면은 인물이다

추상 명사가 등장했다는 이유만으로 그래픽을 만들지 않는다. 발화가 다음 중 하나라면 인물 화면과 강조자막을 우선한다.

- 출연자의 경험과 자기고백
- 반전과 직설
- 기억할 만한 비유
- 경영자의 판단
- 조심스러운 전망이나 의견
- 한 문장만으로 이해되는 정의와 결론

예:

```text
“채용 그만하고 데이터나 팔자”
```

```text
방향을 잡아야 할 선장이
열심히 노를 젓고 있었던…
```

```text
게임이 명확하지 않으면
전략은 사라지고 계획만 남는다
```

이런 발화를 보고 자동으로 단계도·인과도·아이콘 다이어그램을 만들지 않는다.

### 2. 자막은 보고서 요약이 아니라 발화의 리듬이다

좋은 자막은 논리적으로 완결된 보고서 문장보다 실제 말의 캐릭터를 살릴 수 있다.

우선순위:

1. 직접적인 말맛
2. 반전
3. 자기고백
4. 질문과 대답
5. 짧은 정의
6. 구체적인 실행 변화
7. 긴 발화의 결론

경계해야 할 표현:

- `사업 중심 이동`
- `산업 방향 전환`
- `전략 프레임워크`
- `고객 세그먼트 확장`

이런 명사형 표현은 정확하더라도 영상 자막을 분석 보고서처럼 만들 수 있다. 출연자의 문장으로 더 살아 있게 바꿀 수 있는지 먼저 본다.

### 3. 구체적 조직 변화는 각각의 자막으로 살릴 수 있다

여러 실행 변화가 실제 발화의 박자를 이루면 하나의 추상 그래픽으로 압축하지 않는다.

정본 예:

```text
AI 개발 도구 = 클로드로 통일
```

```text
개발 환경 = MacOS로 통일
```

```text
범용 SaaS → 클로드로 자체 사내 도구 제작
```

각 항목이 다른 시점에 발화되고 실제 변화의 구체성을 만든다면 연속 자막이 적절하다. `도구 분산 → 통합 환경 → 자체 도구` 같은 단일 그래픽은 전체 관계를 반드시 한 번에 보여줘야 할 때만 사용한다.

### 4. 프로필·로고·설명자막은 초반 이해 비용을 낮춘다

다음은 장식이 아니라 방향 표지다.

- 출연자 프로필
- 낯선 회사 로고
- 회사·서비스의 한 줄 설명
- 질문 자막

정본은 임승찬·윤우진 프로필, 튜링 로고·설명, 캠핏 설명을 초반에 배치했다. 인터뷰의 대주제를 추상적인 카드 하나로 먼저 선언하느라 이 식별 단계를 생략하지 않는다.

### 5. 질문자막은 장 전환과 답변축을 만든다

모든 질문을 자막화하지는 않지만, 다음 기능이면 사용한다.

- 긴 도입을 끝내고 첫 사례로 들어갈 때
- 사례에서 방법론으로 장이 바뀔 때
- 긴 답변의 평가축을 먼저 알려야 할 때
- 긴 시간 점프 뒤 재진입할 때

질문은 대담에 실제로 존재하는 질문을 살리고, 조수가 더 거대한 논제를 새로 만들어 덮지 않는다.

### 6. 그래픽은 예외적 구조 도구다

조직·경영 인터뷰에서 그래픽을 넣는 조건은 다음과 같다.

- 두 개 이상의 노드와 관계를 동시에 기억해야 한다.
- 순서가 바뀌면 의미가 달라지는 과정이다.
- 비교축이 말만으로는 흩어진다.
- 수치의 분모·기간·전후가 함께 보여야 이해된다.
- 앞뒤 여러 문단을 하나의 방법론으로 회수해야 한다.

그래픽을 쓰지 않는 조건:

- 한 문장의 반전이나 비유로 충분하다.
- 출연자의 감정과 표정이 핵심이다.
- 조심스러운 의견을 프로그램의 단정처럼 만들 위험이 있다.
- 자막 두세 개가 실제 발화의 박자를 더 잘 살린다.
- 그래픽이 단지 발화를 명사형으로 다시 적는 수준이다.

그래픽을 쓰더라도 기획자가 고정할 것은 `핵심 메시지`, `필수 비교축`, `필수 인과·순서`, `수치와 출처`다. 위치, 아이콘, 색, 세부 레이아웃, 모션은 편집자·디자이너에게 맡긴다. 디자이너가 AI처럼 모든 세부 지시를 필요로 한다고 가정하지 않는다.

### 7. 의견성 발화는 인물에게 귀속시킨다

미국·한국 창업자 비교, AI 시대의 기회 같은 발화는 통계적 결론이 아니라 출연자의 관찰일 수 있다. 이런 문단은 자막을 만들지 않고 인물 화면으로 두는 것이 적절할 수 있다.

자막화한다면 `~다`로 확정하지 말고 원문의 가능성·관찰 범위를 유지한다.

### 8. 자료는 식별과 실제 사례를 우선한다

이 유형에서 자료의 핵심 역할:

- 낯선 회사·서비스 식별
- 관련 기사로 사례 진입
- 실제 앱·서비스 화면
- 로고·프로필

일반 AI 분위기 영상이나 추상적 기업 B-roll을 채우지 않는다. 화면구성 문서에 `자료-완료`를 붙이려면 별도 패키지든 링크든 실제 선택 자산이 존재해야 한다.

### 9. 수치·정의·출처는 자막의 말맛과 별도로 검증한다

사용자 문법을 따른다는 이유로 위험한 수치를 그대로 크게 띄우지 않는다.

필수 검사:

- 분모: `취소 고객의 90%`인지 `소비자보호원 관련 민원의 90%`인지
- 귀속: 외부 통계인지 출연자·회사 내부 집계인지
- 시점: 현재 회사 설명인지 과거 사업 설명인지
- 충돌: 같은 원고 안의 `600만`과 `620만`처럼 값이 다른지
- 표현: 출연자는 `피봇`이라고 말하지만 당사자는 이를 부정하는지
- 과장: 경험적 사례를 전체 시장의 확정 사실로 바꾸지 않았는지

팩트 교정은 화면구성의 말맛을 없애는 방식이 아니라, 분모·귀속·시점만 정확하게 고정하는 방식으로 한다.

## 정본에서 배운 실패 패턴

### 조수 작업에서 확인된 실패

- 인물 중심 대담을 구조 설명 영상처럼 처리
- 24개 그래픽을 넣어 모든 추상 발화를 도식화
- 프로필·기본 식별 자료보다 대주제 그래픽을 우선
- 튜링 구간에서 기사·자막·그래픽을 연속 중첩
- 캠핏 사례의 수치·과정·결과를 거의 모두 그래픽화
- 전략론 구간에 질문·정의·비교·단계·시장·결론 화면을 연속 투입
- 조심스러운 의견을 선언형 자막으로 강화
- 모든 메모에 같은 네 항목을 반복해 실제 검토 속도를 저하시킴
- 정확하지만 보고서 같은 명사형 자막을 과도하게 사용

### 수정 원칙

- 사용자 작업본을 베이스로 삼고 그래픽을 예외적으로 추가한다.
- 인물 화면을 `아무것도 안 한 상태`가 아니라 적극적인 기본 선택으로 본다.
- 자막은 압축만 하지 말고 말맛·박자·인물성을 보존한다.
- 한 구간에 자막과 그래픽이 모두 필요하다는 선입견을 버린다.
- 같은 주장을 두 화면으로 재설명하지 않는다.
- 장 전환, 구조 이해, 분모가 있는 수치에만 그래픽 우선권을 준다.

## Word 메모 기준

사용자가 근거 메모를 요청한 경우 실제 Word 댓글 기능을 사용한다.

- 각 생산객체의 `//자막`, `//NN.`, `//그래픽`, `//프로필` 지시 문단에 앵커한다.
- 왜 이 화면이 필요한지 한 문장으로 쓴다.
- 위험한 주장에만 출처·분모·귀속을 한 문장 추가한다.
- `화면 원칙`, `디자이너 판단`, `exact slice` 같은 동일 상용문을 모든 메모에 반복하지 않는다.
- 자막·그래픽을 넣지 않은 모든 일반 문단에 메모를 달아 문서를 오염시키지 않는다.
- 메모는 판단 근거이지 본문 지시를 그대로 반복하는 장소가 아니다.

권장 형식:

```text
선정 이유: 튜링 사례의 핵심 반전인 ‘채용 인력’에서 ‘학습용 코드’로의 수요 변화를 남긴다.
팩트 범위: 기사로 확인되는 것은 코드 데이터 사업이며 5명→500명은 출연자 발언 기준이다.
```

## 같은 유형의 기본 제작 순서

1. 원본 싱크를 읽고 장 전환·질문·반전·자기고백·정의·결론을 표시한다.
2. 프로필과 낯선 회사·서비스 식별 화면을 먼저 확보한다.
3. 인물 화면을 기본으로 놓는다.
4. 사용자 말투에 가까운 자막으로 발화의 박자를 설계한다.
5. 자막만으로 관계가 남지 않는 곳만 그래픽 후보로 올린다.
6. 그래픽 후보마다 `이 관계를 한 번에 보지 않으면 이해가 어려운가?`를 묻는다.
7. 아니면 자막 또는 인물 화면으로 되돌린다.
8. 수치·분모·시점·귀속·충돌을 검증한다.
9. 사용자가 요청한 경우 각 생산객체에 짧은 Word 메모를 단다.
10. 청록 exact-sync, 검정 OUT, 노란 객체, 프로필·자료 호출을 최종 검수한다.
