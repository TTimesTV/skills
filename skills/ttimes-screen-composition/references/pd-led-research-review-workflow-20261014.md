# 전체 회차를 책임지는 PD와 역할 분담

2026-10-14 사용자 승인: 화면구성의 품질은 전체 의미를 이해하고 자료·자막을 선택하는 과정으로 관리한다. 메인 PD + 자료 조사 + 독립 검토를 사용하며, 에이전트 수 자체를 품질 근거로 삼지 않는다.

## 1. 메인 PD가 먼저 결정할 것

- 현재 권위본, 실제 컷 버전, 회차를 확인한다. 연속편은 이전 편의 승인본과 전체 기획을 참고한다. 일정표·폴더·대화에 이미 있는 편수와 담당 정보를 반복 질문하지 않는다. 예정 일정은 완료 증거가 아니다.
- 전체 회차를 읽어 진행자의 질문·재진술, 게스트의 주장·경험·예시, 비교·반전·결론을 연결한다. 인물 이름이나 주제명만으로 자료·자막 유형을 고정하지 않는다.
- 각 의미 단위에서 ‘누가 무엇을 하며, 무엇과 비교하고, 어떤 조건에서 어떤 변화가 생기는가’를 기록한다. 애매한 주체·비교축은 앞뒤 발화로 해석하고, 해소되지 않는 핵심 의미는 미확정으로 남긴다.
- 그다음 시청자가 봐야 할 것을 정한다: 실제 동작, 주장의 근거, 비교 관계, 개념의 구조, 반응·강조, 또는 화자 유지. 자료 없이 발화만 두는 것도 완전한 선택이다.
- 회차의 구성표에는 발화 앵커, 의미, 화면 목적, 제안 유형, 진입·변경·종료, 이전 화면과의 연결을 남긴다. 단어 하나에만 짧게 붙이지도, 무조건 문단 전체에 늘리지도 않는다.

## 2. 역할과 전달 계약

전체 회차의 신규 구성·대규모 재구성에는 메인이 두 보조 에이전트에 다음 역할을 명시적으로 위임한다. 원고를 등분해 서로 모르는 완성본을 합치는 방식은 사용하지 않는다. 단일 자막·앵커 수정에는 메인이 필요한 검사만 수행한다. 관련 스킬의 자료 선정·사실확인·그래픽 제작 지침은 계속 적용한다.

| 역할 | 입력 | 반환해야 할 것 | 결정 범위 |
|---|---|---|---|
| 메인 PD | 전체 권위 원고, 승인 레퍼런스, 사용자 지시 | 회차 구성표와 최종 Word | 의미, 선택, 전체 호흡, 최종 채택 |
| 자료 조사 | 발화와 앞뒤 맥락, 화면 목적, 보여야 할 장면/입증할 주장, 부적합한 대체물 | 실제 확인한 출처·장면, 적합 이유, 출처 영상 IN/OUT 또는 미확인 상태, 대안·미확보 | 후보 조사; 발화 의미나 최종 자료를 임의 확정하지 않음 |
| 독립 검토 | 전체 흐름 요약, 검토 가능한 초안, 근거와 미확정 항목, 사용자 승인 기준 | 위치·오류·근거·필요 수정이 있는 지적 | 오류·누락 검토; 취향만 다른 전면 재작성 금지 |

자료 조사에는 키워드만 보내지 않는다. 예를 들어 ‘공유 AI’ 대신 ‘단체 대화에서 요청 → 개인 AI로 이동해 제작·수정 → 단체 대화로 복귀하는 현재 방식과, 단체 안의 AI가 함께 처리하는 방식의 차이’를 전달한다. 자료가 비슷한 주제라는 이유만으로 그 주장의 증거로 쓰지 않는다.

자료 조사에서 독립적인 후보 검색은 병렬화할 수 있다. 그러나 화면 목적 결정 → 목적에 맞는 조사, 초안 완성 → 독립 검토의 의존 순서는 지킨다. 조사 중 의미가 달라지면 메인에게 반환하고 먼저 해석을 수정한다. 도구 미지원 시 메인이 순차 수행하며 에이전트가 실행됐다고 말하지 않는다.

## 3. 통합과 검토 종료

메인이 조사 결과를 확인하고 문구·자료·시간 전개를 통합한 후 독립 검토를 받는다. 검토자는 다음을 구체적인 발화 위치와 함께 확인한다.

- 주체·행동·비교축·조건이 보존됐는가? 질문이나 가설을 확정 사실로 바꾸지 않았는가?
- 자료가 해당 주장을 뒷받침하는가, 예시·분위기용인가? 실제 화면을 확인했는가?
- 원문 컷과 자막 미선택을 구분했는가? 이전 편의 문구를 새 편에 기계적으로 복제하지 않았는가?
- 강조 범위와 화면 진입·변경·종료가 실제 발화 호흡을 따르는가? 자막과 자료가 충돌하거나 같은 설명을 반복하지 않는가?
- 원문과 Word 서식이 보존되고, 제안 앵커와 진짜 댓글 답글이 연결되는가?

메인은 각 지적을 채택·반려·미확정으로 정리하고 통합한다. 수정 후에는 바뀐 구간과 그로 인해 영향을 받는 연결만 재확인한다. 새로운 오류 없이 전량 조사·검토를 반복하지 않는다. 미확보 자료를 확인 완료로 바꾸거나 미확정 문제를 검증 통과로 덮지 않는다. 원본/편집본 시각과 출처 영상 시각은 별개다.

## 4. JEV는 압축된 판단 보조

메인이 해석한 의미 단위와 필요한 인접 맥락, 적용할 승인 사례, 명시적 선택 기준을 제공한다. 정의가 필요한지, 비교/과정/수치 중 무엇인지, 이전 화면과 중복하는지, 후보가 발화보다 강하게 단정하는지 등 현재 선택에 필요한 질문만 묻는다. 기존 실행기·캐시·실패 규칙은 `jev-judgment-workflow.md`를 따른다.

메인은 불확실하거나 결과를 크게 바꾸는 판단을 직접 검토한다. JEV가 원문을 이해했다고 가정해 해석을 생략하지 않는다. JEV는 출처를 열거나 사실을 검증한 증거가 아니다. 전체 원고·과거 대화를 모든 판단 요청에 반복 첨부하지 않으며, 맥락을 잘라 비용만 줄이지도 않는다. 절감량은 측정 기준이 있을 때만 보고한다.

## 5. 수정 과정의 누적 학습

기존 회차별 비교 보고서와 근거 대응표에 다음 필드를 추가한다. 별도 중복 보관 체계를 만들지 않는다.

`회차·권위 버전·발화 앵커 → 앞뒤 맥락과 의도 → 내 실제 초안 → 사용자 수정/최종 선택 → 수정 이유와 근거 → 적용 조건·반례 → 승인 상태`

이유가 사용자의 명시적 설명인지, 반복 선택에서의 추론인지 구분한다. 승인 상태는 `명시적 승인`, `최종본 채택 확인`, `편집자 수정 전제의 임시 마감`, `검토 중/질문`, `반려`를 구분한다. 임시 마감을 모범 답안으로 삼지 않는다. 단일 사례는 조건부 사례로 보관하고 반복되거나 명시적으로 지시된 기준만 일반 규칙으로 승격한다. 스킬 변경 자체는 실제 새 회차 품질 검증이 아니다.

과정 분석에서 확인한 적용 예:

- 강정수 1편의 ‘먼저 간 기술과 후발 기술’ 수정: ‘기술’로 뭉뚱그리지 말고 비교 주체를 복원한다.
- 유호현의 단체 대화/개인 AI 사례: 추상적인 공유 개념보다 실제 이동·제작·복귀 동작으로 화면 목적을 정의한다.
- 이건복 1편의 성능 격차 자료: 출시 순서만 보여주는 연표가 필요한 비교를 전달하는지 점검한다. 차트 축은 보여야 할 차이에 맞춘다.
- 김지현·정도희 1편 KPI 제안의 ‘편집자가 수정하면 된다’는 마감: 불만이 해소된 최종 디자인 승인으로 기록하지 않는다.
- ‘미니멀’ 피드백: 불필요한 설명을 덜라는 뜻을 필요한 로고·수치·관계까지 지우라는 지시로 일반화하지 않는다.

이 사례는 편집 판단의 근거이며, 언급된 외부 주장 자체의 사실검증 자료가 아니다.
