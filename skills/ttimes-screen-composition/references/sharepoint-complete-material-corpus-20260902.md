# 완료 자료 코퍼스 편집 규칙 (2026-09-02)

개인 저장소 위치와 계정별 수집 내역은 팀 공유본에서 제외했다. 아래는 제작 사례에서 추출한 편집 규칙이다.

## 관측된 실제 문법

- `//NN.` 번호 자료지시: 1,618개
- `//자막` 독립 marker: 2,038개
- `@@` 발화 교정·용어 보충 marker: 678개
- `w:hyperlink` 요소: 70개
- 청록 발화 덮임 색상 `00B0F0`: 403,731자
- 노랑 highlight: 166,151자
- 빨강 계열 run: 41,940자 (`FF0000`, `EE0000`)

## 제작 규칙으로 흡수할 패턴

1. **자료지시는 해당 발화의 바로 앞 독립행**에 둔다.
   - 기본형: `//NN. (대상)_출처_(원본 시각)_실행 장면`
   - 화면 소재, 출처, 영상 원본 시각, 정확한 화면 목적을 한 줄에 묶는다.
   - 예: `//01. (Tactsuit & Tactsuit Air)_bHaptics_(7초~)_착용·진동 작동 인서트`

2. **발화 싱크의 색상 역할을 분리한다.**
   - 검정: 원래 토크 및 자료 OUT 구간.
   - 청록: 해당 자료·그래픽이 실제로 덮는 exact-sync 발화만.
   - 노랑 highlight: 자료·자막·그래픽의 편집 실행 지시.
   - 빨강: 편집자에게 노출되지 않는 PD 주의·검증·수정 메모.

3. **자막은 `//자막`을 독립행으로 두고 확정안만 아래에 쓴다.**
   - 자막이 필요한 논리 단위에만 배치한다.
   - 편집자막의 설명·강조·질문·구조 문구는 `ttimes-editorial-copy` 규칙을 따른다. 말자막의 28자 기준을 편집자막에 일괄 적용하지 않는다. 승인된 긴 설명 카드와 짧은 강조는 별개다.

4. **`@@`는 원문을 대체하는 편집이 아니라 교정·용어 보충의 위치 표시다.**
   - 약어 확장: `@@BCI(뇌-컴퓨터 인터페이스)`
   - 외래어/전문 용어 보충: `@@긍정적 피드백(positive feedback)`
   - 숫자·인과·기술주장은 @@만 남기지 말고 별도 팩트체크 레저에서 원출처를 확인한다.

5. **자료 유형은 번호를 연속 부여하되, 같은 자산의 다른 구간도 각각 정확한 원본시각을 쓴다.**
   - 영상은 출처+원본 시각+보일 동작을 명시한다.
   - 기사·이미지는 `관련 기사 캡쳐_매체_제목`처럼 편집자가 즉시 찾을 수 있게 쓴다.
   - 공식 영상·기사 URL은 가능하면 자료 제목에 하이퍼링크로 연결한다. 링크만 찾은 상태는 자료설계이며, `자료-완료`는 주 스킬의 실제 자산 선택·전달 기준을 충족해야 한다. 새 다운로드가 없어도 기존 전달 자산을 재사용할 수 있다.

## 코퍼스에서 발견됐지만 신규 산출물에는 계승하지 않을 약점

- 미결인 `자막? 그래픽?`와 의도적으로 허용한 편집자 재량을 구분한다.
  - 대상과 허용 범위가 명확한 `(아무 장면)`, `(다른 장면도 ok)`는 `OPEN`으로 유효하다. 의미를 바꾸는 선택만 미결로 남긴다. `그래픽 참고`는 참고용/재제작 지시가 명확한지 확인한다.
- 같은 `//01.`의 반복은 동일 자산 재사용이면 유효하다.
  - 다른 파일·출처에는 새 자산번호를 부여한다. 동일 자산의 새 사용은 기존 번호와 필요한 원본 시각을 유지하고, 내부 placement ID로 구분한다. 화면 등장마다 자산번호를 새로 만들지 않는다.
- 출처만 있고 링크가 없는 사례가 많다.
  - 신규 문서는 제목 하이퍼링크로 원문·원영상에 연결한다.
- 빨간 메모와 최종 실행지시가 섞인 사례가 있다.
  - 납품용 DOCX에는 확정 실행문만 남기고, 조사과정·보류·반론은 내부 레저로 분리한다.

## 적용 우선순위

1. 사용자의 최신 화면구성 규칙(정확한 싱크·구체 지시·하이퍼링크·원문 보존)
2. `ttimes-screen-composition/SKILL.md`
3. 이 코퍼스의 반복 문법
4. 개별 과거 문서의 관행

따라서 이 코퍼스는 시각 문법의 강한 실증 레퍼런스지만, 과거 문서의 모호성이나 출처 누락까지 복제하는 기준은 아니다.
