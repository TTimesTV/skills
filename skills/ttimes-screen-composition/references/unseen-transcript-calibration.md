# 원고 선구성 → 사용자 구성 대조 검증

상태: 운영 절차. 이 문서의 존재는 실력 검증 완료나 자동 평가기 구현을 의미하지 않는다.

## 입력과 오염 방지

- 동일한 승인 컷을 바탕으로 한 깨끗한 원고와 사용자 구성본을 준비한다. Word 버전·발화 순서·영상 컷이 다르면 먼저 대응 관계를 만들고 차이를 분리한다.
- 원고만 보는 작성 단계와 정답을 보는 비교 단계를 분리한다. 작성 단계에는 사용자 자막·자료 파일명·색상 지시·완성 영상·기존 분석을 주지 않는다.
- 이미 본 영상/Word는 반드시 `SEEN_CALIBRATION`으로 표시한다. 새 세션을 만들었다는 이유로 기존 정답 노출을 없었던 것으로 취급하지 않는다.
- 2026-09-06 대화에서 본 NvYtr6wDva8, wbeMT_Rq1Lg 및 기존 학습 코퍼스는 원칙적으로 기노출 사례다. 독립 작성자가 정말 노출되지 않았다는 근거가 있는 별도 시험만 예외다.
- 사용자 승인 사례는 학습용/미노출 평가용으로 분리하고, 개선할 때 평가 정답을 계속 들여다보지 않는다.

## 실행 순서

1. 입력 원고와 비교 기준의 경로·해시·버전·노출 상태를 기록한다.
2. 작성자는 원고만으로 화면구성 후보를 만든다. 기준 영상의 배치 개수나 형태를 미리 알려주지 않는다.
3. 후보를 파일로 저장하고 해시를 고정한다. 그 이후에 비교 기준을 연다. 이미 정답을 본 같은 대화라면 블라인드 시험이라고 부르지 않는다.
4. 발화 앵커 기준으로 후보와 기준을 맞춘다. 단순 행 번호나 서로 다른 편집본의 시각을 직접 비교하지 않는다.
5. 아래 오류 분류로 차이를 검토한다. 이 비교에서 후보를 소급 수정하지 않는다.
6. 애매한 대안과 의도는 사용자에게 좁게 확인한다. 확인 전 상태는 미결로 남긴다.
7. 판정 후 수정 후보를 별도 버전으로 만들고, 유지·폐기·재시험 규칙을 연결한다.

## 비교 단위와 판정

의미 단위의 여러 화면 객체는 한 묶음으로 대조할 수 있다. 일대일 객체 개수 일치를 강요하지 않는다.

- MATCH: 같은 발화 기능을 타당하게 해결.
- FUNCTIONAL_ALTERNATIVE: 그림·자료·문구는 다르지만 같은 이해 과제를 충족. 평가자 제안과 사용자 확정을 구분.
- MISS: 필요한 이해 과제/강조 지점을 놓침.
- EXCESS: 불필요한 자료·설명·강조를 추가하거나 얼굴의 효과를 가림.
- WRONG_FORM: 설명해야 할 구조를 분위기 자료로 대신하는 등 수단이 부적합.
- SYNC_ERROR: 주장은 맞지만 등장·변화·퇴장 발화가 잘못됨.
- CONTINUITY_ERROR: 재정의·중복 강조·잘못된 도해 재사용·이전 설명과 충돌.
- EVIDENCE_ERROR: 자료가 발화의 국가·시점·대상·인과를 뒷받침하지 않음.
- UNRESOLVED: 기준의 의도 또는 자료 대응 관계가 불명확.

주 오류 하나와 필요할 때만 부 오류를 기록한다. 모든 후보 지점뿐 아니라 기준 지점도 살펴 누락을 찾는다. 기준에 없다는 이유만으로 EXCESS로 판정하지 않는다.

## 내부 결과 형식

`발화 앵커 / 후보 선택 / 기준 선택 / 시청자 과제 / 판정 / 근거 / 확정 주체 / 수정 규칙`

집계 시 분모와 단위를 명시한다. 예: ‘검토한 의미 단위’, ‘미결을 제외한 필요 지점’. 초 단위 일치율·문구 유사도·자료 개수는 판단 실력의 대리 점수로 쓰지 않는다. 서로 다른 유효한 구성안은 오답이 아니다.

## 학습과 성능 주장의 경계

- 동작 확인: 규칙·링크·템플릿이 유효하고 예시를 실행했다.
- 기노출 보정: 이미 본 사례와 비교해 오류 유형을 정리했다.
- 미노출 평가: 정답 차단, 후보 선동결, 전 지점 대조, 근거 있는 판정이 실제로 완료됐다.
- 사용자 승인: 해당 후보·대안·규칙을 사용자가 명시적으로 확정했다.

위 상태를 섞지 않는다. 특히 해시/템플릿 검증 PASS는 ‘PD 판단력 검증 PASS’가 아니다. 검증 결과와 최종본 계보는 현재 프로젝트의 인계 문서에 남긴다.
