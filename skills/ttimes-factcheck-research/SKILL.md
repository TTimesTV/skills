# TTimes 팩트체크·리서치

## Overview

티타임즈 원고를 단순히 요약하거나 자막으로 압축하는 데서 멈추지 않고, 실제 공개 가능한 상태인지 검증하는 전용 워크플로다. 사용자가 매번 `팩트체크해`라고 지시해야만 작동하는 반응형 검색이 아니라, 티타임즈 산출물에서 출판 위험이 큰 주장을 발견하면 필요한 검증 과제를 스스로 생성한다.

핵심은 **지시 완수보다 결과물 완성도**다. 다만 자율 확장은 무제한 리서치가 아니다. 최종 문구의 사실성·범위·증거 수준을 바꿀 수 있는 주장만 조사하고, 승인된 컷이나 화자의 취지를 임의로 바꾸지 않는다.

```text
티타임즈 산출물 입력
→ 검증 가능한 주장 탐지
→ 주장 원자화·위험도 평가
→ 팩트체크와 보완 리서치 분리
→ 적합한 전문 리서치 실행
→ 숫자·분모·기간·범위·인과·실행 단계 검증
→ 판정·재현성·한계 정리
→ PD가 바로 쓸 수 있는 수정 문구 제시
```

## When to Use

다음 산출물을 제작·수정·검수할 때 사용한다.

- 컷 전·최종 컷 DOCX, 인터뷰 원고, 내레이션
- 강조자막·설명자막·질문자막·근거자막
- 기사·보고서·차트·자료화면·그래픽
- 제목·썸네일·챕터·설명란·고정댓글
- 공개 전 팩트·오탈자·저작권 QA

다음 신호가 하나라도 있고 최종 공개 문구에 영향을 주면 자동으로 주장 검증 후보에 올린다.

- 숫자, 비율, 점유율, 순위, 시장 규모, 매출, 비용, 사용자 수
- 날짜, 전년·전월 비교, `1년 만에`, `최근`, `현재`
- `최초`, `유일`, `최대`, `대부분`, `90%`, `10억 명`
- 기업·기관의 공식 발표나 특정 인물의 직접 발언
- 기술 성능, 원가, 가격, 아키텍처, 병목
- 계획·검토·실증·도입·양산·상용화·실제 운영 상태
- `A 때문에 B`, `A가 B를 증명`, `그래서 수익이 난다` 같은 인과관계
- 회사를 모델명으로, 모델군을 회사로 부르는 범주 혼용

### Counter-triggers

- 단순한 용어 설명자막 요청은 먼저 용어를 설명한다. 자동화 구조를 장황하게 제시하지 않는다.
- 주관적 감상·전망·전략적 의견은 사실 주장과 분리한다. 의견을 거짓으로 판정하지 않는다.
- 검증 위험이 없는 짧은 표현 수정은 불필요한 웹 리서치로 지연하지 않는다.
- 사용자가 빠른 초안을 요청하면 초안을 먼저 주고, 출판 전 검증이 필요한 항목만 짧게 표시한다.

## Core Distinction: 팩트체크와 보완 리서치

### 팩트체크

이미 원고에 존재하는 주장이 맞는지 검증한다.

```text
“미국 3개 업체 모델 비중이 77%에서 33%로 줄었다”
→ 77%와 33%가 원출처에 있는가?
→ 동일한 지표와 기간을 비교했는가?
```

### 보완 리서치

숫자가 맞더라도 오해를 막기 위해 빠진 조건을 채운다.

```text
점유율의 분모는 토큰·요청·지출·사용자 중 무엇인가?
OpenRouter 내부인가, 전 세계 시장인가?
주간 한 시점인가, 월간 평균인가?
개별 모델인가, 개발사 전체 모델 합계인가?
```

```text
팩트체크 = 틀린 것을 잡는 일
보완 리서치 = 맞지만 오해되는 것을 바로잡는 일
```

두 작업을 연속 수행하되 결과에서는 분리해 보여준다.

## Workflow

### 1. 제작 맥락과 검증 단위를 고정

먼저 산출물과 사용 위치를 확인한다.

```text
산출물 : 원고 / 자막 / 기사 / 그래픽 / 제목 / 업로드 문안
사용 위치 : 내부 검토 / 화면 노출 / 공개 설명란
승인 상태 : 초안 / PD 수정 / 승인 / 동결
```

화면에 노출되거나 제목·썸네일에 쓰이는 주장은 발언 원문보다 높은 위험도로 본다. 완료 기준: 어떤 문구가 실제 공개되는지 식별한다.

### 2. 문장을 원자적 주장으로 분해

한 문장에 여러 사실이 있으면 각각 별도 검증한다.

예:

```text
“오픈AI는 10억 명이 쓰는데 9억 5천만 명이 돈을 안 낸다”
```

분해:

```text
CLAIM-01 오픈AI 관련 서비스 이용자는 10억 명
CLAIM-02 무료 이용자는 9억 5천만 명
CLAIM-03 유료 이용자는 5천만 명
CLAIM-04 유료 전환율은 5%
CLAIM-05 모든 수치의 서비스 범위·시점·분모가 동일
```

원고에 직접 없더라도 자막에서 새로 계산·압축된 `5%`는 새로운 주장이다. 완료 기준: 숫자·대상·기간·인과가 한 주장에 하나씩만 남는다.

### 3. 주장 위험도를 평가

```text
HIGH
법률·안전·명예·직접 인용, 큰 숫자·점유율, 제목·썸네일, 강한 인과, 최초·유일·세계 1위

MEDIUM
기업 전략·도입·양산 상태, 기술 정의·성능, 기사 헤드라인, 설명자막

LOW
일반 배경지식, 화자의 명시적 의견, 결과를 바꾸지 않는 표현
```

HIGH는 원출처와 교차 근거가 없으면 공개 문구를 확정하지 않는다. MEDIUM은 공식 자료 또는 신뢰도 높은 근거를 확보한다. LOW는 과잉 조사하지 않는다. 완료 기준: 모든 검증 후보에 위험 등급과 이유가 있다.

### 4. 전문 리서치 경로를 선택

기본 근거 규율은 `evidence-research-strategy`를 따른다. 주제에 맞으면 해당 전문 스킬을 추가로 사용한다.

```text
AI 플랫폼·모델 점유율·토큰·요청
→ ai-platform-usage-data-audits

반도체·컴퓨팅·메모리·시스템 구조
→ hardware-architecture-claim-audits

인물의 발언·인터뷰·행사 인용
→ public-statement-archive

화면에 붙일 기사·헤드라인
→ 검증 완료 후 ttimes-article-selection

강조·설명·질문자막
→ 검증 완료 후 caption-layering-workflow

전체 화면 지시서
→ 검증 완료 후 ttimes-screen-composition
```

전문 스킬이 없으면 범용 근거 조사로 처리하되, 새 분야의 검증 규칙을 즉석에서 사실처럼 만들지 않는다. 완료 기준: 주장별 조사 경로와 필요한 근거 수준이 정해진다.

### 5. 출처 계층을 적용

팩트 검증용 출처 순서는 기사 첨부용 매체 우선순위와 다르다.

```text
1. 원 발언·원문·공식 보고서·공시·규제기관 자료
2. 공식 데이터·API·제품 문서·방법론
3. 당사자 공식 발표와 파트너의 독립 공식 발표
4. Reuters·Bloomberg·FT·WSJ·CNBC 등 신뢰도 높은 보도
5. 전문 매체·국내 주요 언론
6. 재인용 기사·검색 스니펫·SNS·블로그
```

하위 출처는 발견용으로 쓸 수 있지만, 접근 가능한 원출처가 있으면 원출처까지 올라간다. 완료 기준: 핵심 판정마다 직접 출처 URL·문서명·페이지·발행일 중 가능한 식별자가 있다.

### 6. 범위와 분모를 감사

수치가 일치해도 다음을 모두 확인한다.

```text
대상 : 회사 / 서비스 / 모델 / 모델군 / 국가
분자 : 무엇을 합산했는가
분모 : 토큰 / 요청 / 지출 / 사용자 / 매출 / 전체 표본
기간 : 일 / 주 / 월 / 분기 / 연도 / 롤링 기간
시점 : 기간 평균 / 첫 주 / 마지막 주 / 특정 날짜
표본 : 전체 시장 / 특정 플랫폼 / 특정 고객군 / 자발적 사용자
상태 : 계획 / 계약 / 출하 / 설치 / 운영
```

`ChatGPT`, `OpenAI 모델`, `OpenAI 이용자`를 같은 말로 쓰지 않는다. `월간 점유율`과 `6월 특정 주의 비중`을 혼용하지 않는다. 완료 기준: 최종 문구만 읽어도 대상·지표·기간·표본을 오해하지 않는다.

### 7. 재현 가능성을 별도 판정

출처가 수치를 말하는 것과 공개 원자료로 같은 값을 계산할 수 있는 것은 다르다.

```text
DIRECTLY_REPRODUCED
공개 원자료와 산식으로 동일 수치 재계산

PARTIALLY_REPRODUCED
일부만 계산되거나 숨은 범주 때문에 범위만 확인

SOURCE_STATED_ONLY
신뢰 가능한 출처가 명시하지만 원자료·산식이 비공개

NOT_REPRODUCIBLE
원자료·방법론이 부족해 재현 불가
```

`Others`, 모델 별칭, 무료·프리뷰 변형, 중복 라우트가 있으면 보이는 모델 합계를 전체 개발사 점유율이라고 부르지 않는다. 완료 기준: 정확한 숫자를 직접 계산했는지, 출처를 인용한 것인지 명시한다.

### 8. 판정하고 교정 문구를 만든다

판정 코드는 다음을 사용한다.

```text
PASS          출처·숫자·범위·표현이 정확
CORRECTED     핵심 취지는 맞지만 숫자·명칭 오류
QUALIFIED     사실이지만 기간·분모·표본 조건이 필요
UNREPRODUCIBLE 출처 수치는 있으나 공개 원자료로 재계산 불가
UNVERIFIED    신뢰할 근거를 확보하지 못함
FALSE         원출처와 명백히 불일치
OPINION       검증 대상이 아닌 의견·전망
```

원고를 몰래 덮어쓰지 않는다. `원문`, `판정`, `교정안`을 분리한다. 승인된 컷 DOCX를 수정하라는 요청이면 사용자의 교정 로케이터 규칙에 따라 고친 단어 앞에 `@@`를 붙여 편집자가 찾게 한다. 화면 문구에는 `@@`를 노출하지 않는다. 완료 기준: PD가 유지·수정·삭제 중 하나를 즉시 결정할 수 있다.

### 9. 자막·기사·그래픽에서 파생된 새 주장을 재검증

압축 과정에서 강도가 높아질 수 있다.

```text
원 발언 : “사용자가 10억 명이고 대부분 무료다”
강조자막 : “오픈AI 유료 전환율 5%”
```

두 수치의 기준과 시점이 다르면 계산상 그럴듯해도 자막은 틀리다. 기사 제목, 그래프 축, 비교 화살표, 제목·썸네일 문구도 각각 새 주장으로 등록한다. 완료 기준: 공개 화면의 모든 수치·강한 판정이 검증된 주장과 연결된다.

### 10. PD 승인용으로 압축

조사 로그보다 결론을 먼저 보여준다. 미해결 항목이 있으면 `확인 불가`를 숨기지 않는다. 완료 기준: 첫 화면에서 판정과 사용할 문구를 확인할 수 있고, 뒤에서 근거를 추적할 수 있다.

## Required Output

### 짧은 단일 주장

```text
판정 : CORRECTED

원문 : 77% → 33%
정확한 수치 : 72% → 33%
정확한 범위 : OpenRouter 주간 토큰 중 Google·OpenAI·Anthropic 모델 합산 비중
주의 : 전체 AI 시장점유율로 일반화 불가
재현성 : SOURCE_STATED_ONLY 또는 PARTIALLY_REPRODUCED
출처 : 문서명·페이지·직접 URL
```

```text
[최종 원고 또는 자막]
```

### 복수 주장 또는 전체 원고

| ID | 원문 주장 | 위험도 | 판정 | 문제 | 정확한 범위 | 재현성 | 수정안 | 핵심 출처 |
|---|---|---:|---|---|---|---|---|---|

표 아래에는 다음만 덧붙인다.

```text
즉시 수정
추가 확인 필요
그대로 사용 가능
```

### 내부 구조화 객체

```json
{
  "claim_id": "CLAIM-001",
  "segment_id": "SEG-0142",
  "source_text": "원래 발언",
  "derived_text": "압축 자막 또는 그래픽 문구",
  "claim_type": "NUMERIC_COMPARISON",
  "risk": "HIGH",
  "metric": "weekly_token_share",
  "numerator": "Google+OpenAI+Anthropic model tokens",
  "denominator": "all OpenRouter tokens",
  "period": ["2025-06", "2026-06"],
  "verdict": "QUALIFIED",
  "reproducibility": "SOURCE_STATED_ONLY",
  "source_url": "direct source",
  "corrected_text": "PD가 사용할 교정안",
  "pd_status": "DRAFT"
}
```

JSON은 내부 추적용이다. 사용자가 단일 자막만 요청했는데 JSON부터 보여주지 않는다.

## Gold Example: OpenRouter

입력:

```text
2025년 6월 GPT·Gemini·Claude 점유율 77%
2026년 6월 33%
```

필수 탐지:

- `77%`의 원출처 수치 확인
- GPT·Gemini·Claude와 OpenAI·Google·Anthropic 전체 모델 구분
- 점유율의 단위가 토큰인지 요청인지 확인
- 주간 시점과 월평균 구분
- OpenRouter 표본을 전체 시장으로 일반화하지 않음
- `Others` 때문에 공개 차트에서 재현 가능한지 확인

출력 방향:

```text
판정 : CORRECTED + QUALIFIED
77%가 아니라 출처 표기는 72%.
전체 시장점유율이 아니라 OpenRouter 주간 토큰 비중.
정확한 합산 수치는 Exponential View의 OpenRouter 데이터 분석.
```

## Bounded Autonomy

자율 리서치는 다음 조건을 모두 만족할 때만 확장한다.

1. 검증 결과가 공개 문구를 바꿀 수 있다.
2. 주장이 객관적으로 확인 가능하다.
3. 출판 리스크가 MEDIUM 이상이다.
4. 현재 요청을 과도하게 지연하지 않는 조사 경로가 있다.

긴 조사가 필요하면 현재 산출물과 검증 상태를 분리한다.

```text
초안 제공 가능
단, CLAIM-03은 공개 전 추가 검증 필요
```

사용자가 명시적으로 중단하면 자동 조사를 재개하지 않는다.

## Common Pitfalls

1. **모든 문장을 리서치로 확장**
   - 공개 문구를 바꿀 수 있는 경성 주장만 조사한다.

2. **정확한 숫자만 고치고 범위를 방치**
   - 분모·기간·표본·개발사 묶음을 함께 교정한다.

3. **기사를 원출처로 착각**
   - 접근 가능한 보고서·공시·원발언까지 올라간다.

4. **공식 데이터와 제3자 재분석을 혼용**
   - 플랫폼이 제공한 원자료와 분석자가 만든 합산 수치를 분리한다.

5. **출처 기재와 직접 재현을 동일시**
   - 재현성 상태를 별도로 표시한다.

6. **화자의 취지를 팩트체크 명목으로 재작성**
   - 원문은 보존하고 교정안을 별도로 제시한다.

7. **자막 압축에서 새 주장을 놓침**
   - 계산·단정·비교가 추가되면 다시 등록한다.

8. **기사 선정부터 시작**
   - 주장 자체를 검증한 뒤 화면 증거 기사를 고른다.

9. **간단한 자막 요청을 장문의 시스템 설계로 전환**
   - 요청 산출물을 먼저 주고 필요한 검증 경고만 붙인다.

10. **원자료 접근 실패를 그럴듯한 수치로 메움**
   - `UNVERIFIED` 또는 `NOT_REPRODUCIBLE`로 남긴다.

## Verification Checklist

- [ ] 실제 공개될 문구와 내부 발언을 구분했다.
- [ ] 문장을 원자적 주장으로 분해했다.
- [ ] 자막·그래픽에서 파생된 계산 주장도 등록했다.
- [ ] 숫자·분모·기간·대상·표본·실행 단계를 확인했다.
- [ ] 팩트체크와 보완 리서치를 분리했다.
- [ ] 적합한 전문 리서치 스킬을 사용했다.
- [ ] 원출처와 제3자 분석을 구분했다.
- [ ] 재현 가능성을 별도로 판정했다.
- [ ] 승인된 컷을 몰래 수정하지 않았다.
- [ ] 최종 판정과 복붙 가능한 교정 문구를 먼저 제시했다.
- [ ] 미해결 항목과 필요한 추가 증거를 명시했다.
- [ ] 기사·자막·그래픽·제목의 새 주장까지 최종 교차검증했다.
