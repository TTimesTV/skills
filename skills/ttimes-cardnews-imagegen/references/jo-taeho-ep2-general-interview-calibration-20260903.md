# 조태호 2편 일반 대담형 카드뉴스 교정 — 2026-09-03

## 적용 범위

TTimes 일반 대담형 5장 카드뉴스, 특히 기술 인터뷰를 실용 강의·메커니즘 이야기로 압축할 때의 사용자 교정 사례다. 현재 회차의 명시 지시가 항상 우선하며, 이 문서는 반복 가능한 선택 원리를 기록한다.

## 승인된 이야기 구조

```text
사람과 실용성을 함께 드러내는 표지
→ 익숙한 방식의 한계
→ 새 방식의 작동 원리와 함정
→ 외부 통제 해법
→ 사람이 맡길 범위를 정한다는 단정적 회수
```

조태호 2편에서는 다음 순서가 성립했다.

```text
미국 의대 교수가 말아주는 바이브코딩 강의
→ 웹이 아니라 로컬 폴더에서 작업
→ 여러 AI가 돌려보는 루프와 집단 오판
→ 외부 코드가 경로를 정하는 그래프
→ 어디까지 맡길지 사람이 먼저 정함
```

## 사용자 워딩 취향

### 1. 사람·행동·효용이 먼저 보이는 제목

승인 표지:

```text
미국 의대 교수가 말아주는
바이브코딩 강의
```

- `그래프 엔지니어링의 원리`, `AI 통제 방식`처럼 기술 분류를 앞세우기보다, **누가 무엇을 해주는지**를 먼저 보여준다.
- 전문성은 `미국 의대 교수`처럼 구체적 신뢰 표지로 짧게 제시한다.
- `설명하는`, `소개하는`보다 `말아주는`처럼 콘텐츠의 실용성과 구어적 재미가 동시에 느껴지는 동사를 선호한다.
- 구어적이라고 해서 밈이나 유행어를 여러 개 쌓지 않는다. 강한 표현은 하나만 쓴다.

### 2. 보고서형 주체 소개를 본문 첫머리에 두지 않음

거절 신호:

- `조태호 연구팀은 ~를 연구했다` 같은 연구 소개체
- 정의·분류·배경부터 시작하는 교재식 문장
- 기술 용어를 제목과 첫 문장에서 반복하는 설명문
- 정확하지만 갈등·행동·독자 효용이 없는 `노잼` 말투

선호 순서:

```text
독자가 지금 하는 행동 또는 익숙한 장면
→ 그 방식의 문제
→ 구체적으로 무엇이 바뀌는지
→ 기술명 또는 해법
```

### 3. 본문은 짧은 개조식 행이 아니라 두 개의 연속 문단

- 각 카드 본문은 보통 **두 문단**으로 구성한다.
- 소스에는 문단 문자열을 저장하고 실제 행갈이는 렌더러가 처리한다.
- 문장을 짧게 잘라 왼쪽에 층층이 쌓지 않는다.
- 승인된 왼쪽 정렬 레이아웃은 유지하고, 문장 길이와 줄바꿈 지점을 조정해 각 행이 카드 중앙 너머까지 자연스럽게 뻗게 한다.
- 시각적 쏠림 문제를 중앙 정렬이나 새 레이아웃으로 해결하지 않는다.
- 문법적으로 결속된 구절을 임의로 분리하지 않는다.

### 4. 한 카드 안의 문장 역할을 분리

권장 2문단 구조:

```text
1문단: 메커니즘 또는 실제 동작
2문단: 함정·통제·판정 등 핵심 결론
```

루프 카드의 경우 `작성·검토·수정의 반복` 뒤에 `여러 AI가 같은 오류를 놓칠 수 있음`을 둔다. 그래프 카드의 경우 `성공·재시도·사람 승인 경로` 뒤에 `AI 바깥 코드가 경로를 고정함`을 둔다.

### 5. 결말은 중립적 요약보다 인간의 책임을 단정적으로 회수

승인 마무리:

```text
AI를 잘 다루는 방법은
더 많은 일을 맡기는 게 아닙니다.

어디까지 맡길지
사람이 먼저 정하는 겁니다.
```

- 첫 문단은 통념을 꺾고, 두 번째 문단이 핵심 판단을 회수한다.
- 강조는 두 문단에 분산하지 않고 **두 번째 문단 전체**에 둔다.
- `중요합니다`, `필요합니다`, `고려해야 합니다` 같은 일반론으로 끝내지 않는다.

## 비주얼 교정

### 비유 승인 선행

추상 기술 개념의 이미지가 `직관적이지 않다`고 거절되면 즉시 재생성하지 않는다. 먼저 개념을 한 문장의 물리적 비유로 설명하고 승인을 받는다.

- 루프 엔지니어링: 작성자→검토자→수정자가 원고를 계속 돌려보지만 같은 오류를 모두 놓치면 오류도 함께 순환하는 회람.
- 그래프 엔지니어링: AI는 차이고 외부 코드는 신호등·차단봉·고정 도로망이며, 완료·재시도·사람 승인 중 허용된 길로만 이동.

두 비유는 `계속 돌림`과 `갈 수 있는 길을 외부에서 고정함`이 이미지 자체에서 대비돼야 한다.

### `image gen만`의 의미

- 생성 이미지 위에 의미를 보강한다는 이유로 로컬 캡슐, 설명 라벨, 화살표, 박스, 가짜 UI를 후합성하지 않는다.
- 카드 번호·제목·본문·강조처럼 승인된 **카드 템플릿 레이어**는 결정론적으로 합성할 수 있다.
- 의미 관계와 행동은 image-generation 결과 자체에서 읽혀야 한다.

### 피그마 톤의 합격 기준

`밝은 배경`만으로는 부족하다. 다음을 모두 확인한다.

- 흰색 또는 아주 밝은 회색 배경
- 2D 플랫 벡터·단순 기하형
- 코발트·퍼플·코랄·옐로 등 선명한 제한 팔레트
- 넓은 여백과 또렷한 관계선
- 검은 배경, 네온, 포토리얼 CGI, 아이소메트릭 3D, 유리·금속 광택, 젖은 재질, 안개 금지
- 실제 1080×500 카드 크롭에서 핵심 경로와 오브젝트가 온전히 보이는지 검사
- 같은 시퀀스의 2~4장은 동일한 팔레트·외곽선·아이콘 문법으로 접촉면 QA

## 승인·잠금과 수정 범위

- 사용자가 `5장은 통과`라고 하면 마무리 문구·강조·프로필·레이아웃을 잠근다.
- 이후 `2장도 톤에 맞게`처럼 범위가 특정되면 해당 이미지와 전체 접촉면만 갱신하고 잠긴 카드의 내용은 바꾸지 않는다.
- 이미지 시안에 대한 `ㄱㄱ`는 해당 시안 적용 승인이다. 이를 본문·표지·잠긴 카드 재작성 승인으로 확대하지 않는다.

## 업로드 설명과 메타인지 게이트

사용자가 `아까 에르메스한테 시킨 설명`, `기존 설명 복붙`처럼 **기존 문구의 회수**를 요청하면 창작 요청이 아니다.

1. 작업 폴더, 메타데이터 파일, 세션 기록에서 exact 문구를 검색한다.
2. 찾으면 원문을 그대로 복붙한다.
3. 찾지 못하면 `기존 문구를 찾지 못했습니다` 또는 `모르겠습니다`라고 답한다.
4. 비슷한 새 설명을 만들어 기존 문구인 것처럼 대체하지 않는다.
5. 사용자가 원문을 제공하면 그 문구를 새 권위 원본으로 보존하고, 요청 범위 밖의 윤문을 하지 않는다.

이번 실패: 기존 업로드 설명을 찾지 못한 뒤 카드뉴스 내용을 토대로 새 설명을 만들어 전달했다. 이는 카피 품질 문제가 아니라 **검색 실패를 창작으로 덮은 메타인지 실패**다.

사용자가 제공한 권위 문구:

```text
“바이브 코딩이라 하면 내가 가지고 있는 정보를 내 컴퓨터로 가지고 와서 저장시키면서 만들어야 되는 게 기본 중의 기본입니다. claude.ai 주소의 양옆에 붙어 있는 이 키워드를 알면 바이브코딩의 마법이 시작됩니다.” 현직 영상의학과 교수이면서 AI를 통해 알츠하이머 조기진단을 연구하고 있는 조태호 인디애나 의과대학 영상의학과 교수에게 바이브코딩의 팁을 들어봅니다.
```

이 문구는 사용자가 제공한 업로드 설명 원문이다. 카드뉴스 본문이나 새 요약으로 대체하지 않는다.
