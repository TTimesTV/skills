# Infrastructure Demand-First Hook Calibration

Use when a 45–75 second technical short must open with **why an infrastructure system is needed** before introducing a candidate technology.

## Durable lesson

If the PD says a context must appear first, this is not an insertion request. Rebuild the causal spine so the context is the opening problem and the ending's return point.

```text
demand-side pain
→ bounded role of the infrastructure system
→ candidate technology reveal
→ physical weakness
→ physical reversal within ~15 s
→ evaluation-axis change
→ system-level cost / operating caveat
→ return to the original demand problem
```

A technology-first hook with one demand sentence added later still violates the requested story order.

## Hook requirements

- First 1–2 lines must name the user's required problem space.
- Keep the first sentence short enough to understand before the second visual cut.
- Preserve a collision: `continuous demand ↔ variable supply`, `moving product ↔ stationary system`, or equivalent.
- Reveal the candidate by about 6–10 seconds.
- Land the strongest physical reversal by roughly 15 seconds; if demand context pushes it later, compress setup rather than delaying the reversal.

## Data-center + ESS factual safety

Safe distinctions:

- Data centers need reliable power; ESS can support peak response, time shifting, ride-through, or power quality according to its rated power and duration.
- ESS stores and later discharges electricity. It does not generate primary energy.
- Do not imply every data center must use the same ESS architecture or that one battery can carry the entire site indefinitely.
- For stationary batteries, mass and volume penalties are usually less severe than in vehicles, but land, racks, wiring, foundations, cooling, fire protection, PCS/inverters, and integration still affect turnkey cost.
- Abundant sodium can support supply diversification; it does not prove that a finished sodium-ion BESS is currently cheaper, safer, longer-lived, or commercially mature versus LFP.
- Use `candidate`, `may`, `potential`, and `needs operating data` when field evidence is limited.

## Reusable one-minute beat map

```text
0–5 s   required infrastructure problem
5–10 s  what the system does, with one boundary
10–15 s candidate reveal + physical reversal
15–30 s why the old penalty shrinks in this setting
30–43 s evaluation criteria change
43–55 s system-level cost and operating evidence caveat
55–65 s return to the opening infrastructure problem
```

## 90-point gate

Score the actual integrated revision, not an earlier reviewer draft.

- Hook: required context is present immediately and contains a collision.
- Structure: context is causal, not decorative.
- Retention: physical reversal appears by ~15 seconds.
- Clarity: the infrastructure role is bounded in plain language.
- Fact safety: no generation, indefinite-backup, universal-winner, or raw-material-to-turnkey-cost leap.

Do not award 90+ if the PD's required context is still secondary, even when the standalone hook is punchy.

## Iteration pitfalls

When a PD first asks for a stronger hook and then says a domain context must come first, the second instruction wins. Do not defend or preserve the previous hook merely because reviewers scored it highly. Rebuild and return the **whole script** after each structural correction.

### Mechanical-neutrality ending

Do not let factual caution become the final message. A sequence such as:

```text
not a confirmed winner
→ not necessarily cheaper
→ may not be disqualified
```

is accurate but leaves the audience unable to state the thesis. Put those limits in the 43–55 s `cost / operating caveat` beat. End by naming the candidate's actual competitive arena and the criterion that changes there.

Preferred ending shape:

```text
[candidate] targets [specific infrastructure arena].
In that arena, [mechanism-backed criterion] decides the competition.
```

Calibrate certainty with verbs such as `노린다`, `겨냥한다`, `평가축이 바뀐다`, or `승부를 가른다`; do not claim inevitable adoption or victory.

### Hook metaphor that carries the mechanism

A contrast such as `창고가 아니라 공장` works only if its second half supplies the next causal beat. For AI infrastructure, `서버를 쌓아둔 창고가 아니라, 전기로 지능을 만드는 공장` immediately creates the dependency `continuous electricity → buffering/storage need`. Use the metaphor once, then move into the mechanism; do not repeat it as decoration throughout the script.
