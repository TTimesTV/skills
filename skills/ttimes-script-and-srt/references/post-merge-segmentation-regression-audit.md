# Post-merge segmentation regression audit

Use when a new immutable cue-body candidate was generated by applying many findings from one or more prior segmentation reports.

## Core lesson

A prior finding's proposed redistribution is not automatically safe. It can repair the named split while creating a new one at the replacement boundary. In a regression audit, review the current candidate independently; use the predecessor diff only to locate changed windows.

## Procedure

1. Freeze/hash the exact current candidate and record bytes, line count, and requested cue range.
2. Read every cue and every adjacent boundary in scope. Include the seam immediately outside the requested end when assigned.
3. Diff predecessor→current only after the independent read. Enumerate every changed window and re-read:
   - all replacement cues;
   - the boundary immediately before the window;
   - the boundary immediately after it.
4. For every old fix, test both directions:
   - Did the intended protected phrase become whole?
   - Did the repartition strand a new 관형어/관형절, 관형격, 의존명사, 목적어/부사어, 보조용언, 수량+단위, comparison phrase, quote particle, or tiny connective?
5. Do not inherit the old report's wording or verdict. Exact-search the current multiline string and describe only the defect present in the current hash.
6. A confirmed regression needs a token-preserving alternative whose every cue is within the current visual maximum and whose new boundaries do not merely recreate another avoidable protected split.
7. For genuinely long syntax where every ≤27 split breaks some relation, choose the least harmful readable boundary and do not inflate findings. Count it only when a materially better lossless redistribution exists.
8. Validate each finding mechanically: current block unique exact-match, whitespace-normalized token stream preserved, proposal max length valid, heading/current/proposal counts equal, opening and closing candidate hashes equal, and no candidate edits.

## Recurring regression patterns

These appeared after bulk application of otherwise valid-looking fixes:

- Moving repeated modifiers together but leaving the center noun behind: `인베스트먼트에 대한 투자에 대한 / 리턴만 ...`.
- Moving a noun to the next cue while stranding its adnominal clause: `반도체가 담기는 / 그릇이라고 ...`.
- Splitting a comparison immediately after `대비`: `Blackwell 대비 / Vera Rubin에서`.
- Fixing an adnominal+noun split by creating a degree-adverb+predicate split: `겁나게 많이 / 팔았으면 ...`.
- Moving a predicate beside its object but stranding an adjective from the noun: `대단히 큰 / 이런 것을 ...`.
- Breaking a long adverbial noun phrase internally even though the intact phrase fits the box: `다른 데이터의 / 네오클라우드 사업자들 중에`.

## Reporting contract

Return one headline `PASS`/`FAIL`, exact scope and seam, immutable hash facts, arithmetic-checked confirmed regressions, exact current multiline strings, token-preserving redistributions with lengths, and an explicit no-candidate-edit statement. Keep source fidelity, terms, and factual accuracy outside the verdict when the user assigned segmentation-only review.
