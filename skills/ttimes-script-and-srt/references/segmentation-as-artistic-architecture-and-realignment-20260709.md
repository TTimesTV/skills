# TTimes/SRT 분절 재작업 교훈 — 2026-07-09

## 핵심 교정

사용자는 `분절 업무`를 단순 SRT 생성/자동 줄바꿈이 아니라 **화면 속 자막 바를 독자가 어떻게 읽을지 설계하는 예술적 아키텍처 작업**으로 규정했다.

따라서 평가 기준은 평균점수가 아니다.

```text
형식/타임코드/27자 통과 = 전제조건
분절 품질 = 최종 점수의 지배항
분절이 45점이면 전체도 45점
```

## 실패 패턴

기계적 27자 wrapping은 다음 같은 실패를 만든다.

```text
AI를
분들도
취재하고
너희는
회사 전체가
인사이트를
데이터
수
```

이런 cue는 길이는 짧아도 독자가 다음 cue를 기다려야 의미가 닫히므로 말자막으로 실패다.

## 올바른 작업 순서

1. `/plan`으로 업무 정의를 `SRT 생성`이 아니라 `분절 편집`으로 고정한다.
2. 전체 진행 전에 0~3분 샘플 분절을 만든다.
3. 사용자에게 샘플 감각 승인을 받는다.
4. 승인 후 subagent에게 파트별 초벌 분절을 맡긴다.
5. Main이 편집장 역할로 하나의 리듬으로 통합한다.
6. 마지막에 word timestamp로 SRT를 정렬한다.
7. 최종 검증은 형식검사 + 사람 눈 분절검사 + 샘플 싱크검사까지 포함한다.

## 자막 문장부호

금지는 `문장 끝 기계적 마침표 .`이지 문장부호 전체 제거가 아니다.

살려야 할 수 있는 문장부호:

```text
?  실제 질문/반문
!  제한적 강조
,  호흡/목록/대비
" " / ' '  인용, 프롬프트, 용어, 제목, 강조
```

질문 cue에 `?`가 없으면 대화 리듬이 죽는다.

## subagent 사용법

subagent는 최종 편집자가 아니라 초벌 노동자다.

```text
subagent = 파트별 caption_body 초벌
Main = 전체 리듬 통합/검수/최종 책임
```

subagent에게는 승인된 샘플을 기준으로 다음을 명시해야 한다.

```text
원발화 보존·최소교정
문장/생각 끝나면 다음 cue
작은문장성
목적어/부사어/시간어/접착어 고립 금지
공백 포함 25자 목표/27자 max
자막 문법상 필요한 ?, !, 쉼표, 따옴표 보존
```

## 정렬 교훈

caption body를 다시 만든 뒤 SRT 타임코드를 붙일 때 전체 길이 비례 매핑을 쓰면 중후반 배치가 밀릴 수 있다.

권장:

```text
최종 caption body 문자열
↔ ASR word stream 문자열
fuzzy/sequence match 기반으로 cue를 실제 발화 단어 위치에 매핑
```

비례 매핑은 빠른 초안용으로만 쓰고, 최종본에는 사용하지 않는다.

## 최종 판정 언어

`타임코드 오류 0`, `27자 초과 0`, `마침표 0`은 품질점수가 아니라 납품 최소조건이다. 분절 업무에서는 이 수치로 점수를 끌어올리면 안 된다.
