# 2026-07-13 박영선–박남규 기술대담 샘플 승인 교훈

## 적용 상황

자막이 없는 40분 안팎의 한국어 기술 대담을 `YouTube → chunked MLX ASR → 0~3분 승인 샘플 → 전체 말자막`으로 만드는 경우.

## 확인된 실패 패턴

첫 샘플이 읽기 좋게 보이도록 고치면서 실제 발화의 반복·연결어·조사·자기수정까지 지워졌다. 분절 reviewer만 따르면 더 매끄럽지만 원문에서 멀어질 수 있다.

예:

- `가보도록 하겠습니다` → `가보겠습니다`: 불필요한 말투 삭제
- `태양전지, 태양전지 말씀` → `태양전지 이야기`: 반복과 어휘 변경
- `석유화학` → `석유, 화학`: 의미 왜곡
- `신재생에너지에서 얻는 전기가 필요합니다` → `신재생에너지에서 전기를 얻어야 합니다`: 주장 구조 변경
- `AI 데이터센터 같은 데` → `AI 데이터센터에`: 범위 축소

## 승인 샘플 전 필수 3중 리뷰

1. **원문충실도:** ASR과 모든 샘플 cue를 대조해 삭제·압축·자기수정 제거·범위 변경을 찾는다.
2. **분절:** 모든 인접 cue를 읽어 관형어+명사, 의존명사, 목적어·부사어+서술어, 보조용언, 수량+단위를 판정한다.
3. **기술용어:** 고유명사·약어·화학명·숫자·단위를 공식 자료와 targeted clip ASR로 확인한다.

분절 reviewer의 최소윤문안과 원문충실도 reviewer의 복원안이 충돌하면 **원발화 보존이 우선**이다. Main이 보호 결합구만 다시 설계한다.

## 사실 오류와 ASR 오류 구분

- 공식 역사·기술 사실과 다르더라도 targeted ASR에서 화자가 실제로 그렇게 말했다면 자막은 발화를 유지한다.
- 예: 공식적으로는 벨연구소가 맞더라도 화자가 반복해서 `IBM`이라고 말했다면 `IBM`을 유지한다.
- 반대로 `흡광 개수`, `비어 람베드`, `적청`, `24%7`처럼 문맥과 공식 용어가 일치하는 명백한 ASR 오류는 `흡광계수`, `비어-람베르트`, `적층`, `24/7`로 고친다.
- 이 판정을 `correction_ledger.json`에 `from/to/basis`로 기록한다.

## Targeted ASR 사용법

고위험 표현은 전체 ASR을 전역 치환하지 말고 10~90초 클립으로 재전사한다. 프롬프트에는 후보 용어만 좁게 넣는다. 클립이 너무 짧아 문장 경계를 놓치거나 반복 hallucination이 생기면 시작점을 5~10초 앞당겨 재시도한다.

## 승인 샘플 동결

- 승인 샘플의 비어 있지 않은 줄을 별도 파일로 저장한다.
- SHA-256, 줄 수, 최대 글자 수, 승인된 길이 예외를 manifest에 기록한다.
- 전체 본문의 정확한 prefix인지 매번 확인한다.
- 27자를 넘는 보호 결합구가 있으면 샘플에서 명시하고, 사용자가 그 샘플을 승인했을 때만 예외로 동결한다.

## 전체 초벌 reviewer freshness

전체 후보를 만들면 해시를 먼저 고정하고 reviewer에게 그 해시와 담당 줄 범위를 준다. reviewer가 검토하는 동안 본문은 수정하지 않고 Main의 용어 판정은 별도 ledger에 쌓는다. 리뷰가 끝난 뒤 한 번에 통합하면 stale line-number와 구버전 제안 적용을 줄일 수 있다.
