### 6. Subagent review structure — mandatory for this workflow

For this user's TTimes spoken-caption / YouTube-to-script-SRT workflow, **always start with an explicit /plan-style workflow before regenerating files**, especially after quality failures or rule changes. Planning prevented repeated mechanical packing failures by fixing priority order before execution. Also **always use subagents**. The number of subagents is up to Main Hermes, but using zero subagents is not acceptable for this task class. User delivery preference: normally deliver only the final `*_srt.txt`; do not include long meeting minutes/reports unless the user asks. If the user asks for timecode-free text, deliver only the script/body text. Subagents may create **bounded preliminary range drafts** when the user's workflow calls for `MLX + subagent 초벌·리뷰 → Main 통합`, but they are never independent final-script authors. Main must verify each draft file/hash, repair cross-range boundaries and stale ASR-hole intervals, apply the correction ledger, integrate one whole-body rhythm, and run current-hash term/segmentation/omission reviews before freeze. A subagent self-report or range draft is review material, not a final deliverable.

**Hard range-containment rule:** before dispatching a bounded drafter, physically extract the exact timestamped source slice (prefer 5–10 minute slices for long videos), save and hash it, and give the subagent **only that slice** plus glossary/ledger references. Do not also provide a full timecode-free baseline or full raw transcript: a drafter can ignore the requested time bound and continue through the unbounded file, then self-report a false range. Require the result to report the slice's first/last timestamps and source hash. Main must inspect the actual opening/ending text, not just line counts or the subagent summary. If content crosses the slice boundary, quarantine the artifact under `obsolete/` and regenerate from exact slices; never splice a scope-invalid draft into the final body. If a 20-minute slice approaches output/context limits, split it into two 10-minute sources instead of asking the drafter to compress. See `references/bounded-subagent-source-slice-containment.md` for the failure signature, extraction recipe, verification gate, and quarantine procedure.

**Wall-clock speed without token or quality cuts:** preserve the full spoken content, reasoning level, and review axes; reduce elapsed time through orchestration instead. Start auto-caption extraction, MLX chunk ASR, and term reconnaissance as soon as their inputs exist. Use exact 5–10 minute slices and dispatch all independent range drafts concurrently up to the configured safe limit. Before immutable review, run the deterministic body/protected-phrase pre-pass once so reviewers do not discover obvious subject–predicate and question–answer splits across many serial generations. On one frozen hash, run source/term reviews by time half and segmentation reviews by cue half in parallel, merge all accepted findings once, then perform one strict zero-blocking-finding convergence generation. Do not serialize reviewers that can inspect the same hash independently. `/fast fast` may reduce model API latency when the active provider/model supports it, but it does not accelerate local MLX/FFmpeg; never substitute lower reasoning, summary, or dropped repetitions for speed. Increasing `delegation.max_concurrent_children` is a workflow change and requires user approval because it changes resource/rate-limit behavior. See `references/long-form-exact-slices-and-finite-review.md` and `references/finite-segmentation-convergence-and-severity.md`.

Use `references/2026-07-08-predicate-attachment-caption-workflow.md` as the compact session-derived playbook for the successful rebuild pattern: `/plan` first, reuse ASR/confirmed term fixes, rebuild with sentence-ending + predicate-attachment priorities, brief subagents to find stranded object/adverbial/time phrases, then rerun SRT alignment and validation.

User subtitle style corrections:
- Do not put mechanical sentence-final periods/full stops in 말자막 body lines. This does **not** mean stripping all punctuation. Preserve or add subtitle-useful punctuation when it carries viewing rhythm or meaning: question marks `?` for real questions/반문, occasional `!` for emphasis, commas for list/rhythm, and quotes `" "` / `' '` for quoted speech, prompts, terms, titles, or self-contained embedded text. The rule is: remove dead prose periods, but design living subtitle punctuation.
- Sentence/thought boundary is a high-priority cue boundary: when one sentence or complete thought ends, usually move the next sentence to the next cue. Do not pack two completed sentences/questions into one cue merely because the combined text fits under 27 chars. Example: prefer `아직 버전 아니에요? / 아, 끝난 거 아니에요?` as separate cues.
- When filler/transition words such as `뭔가` appear mid-thought, prefer splitting before `뭔가` so the previous semantic unit closes first, e.g. `그게 요새 조금 꺾이면서 / 뭔가 이제 한 사이클이 좀 변해가고 있는 느낌이 드는데`.
- Treat `지시어+의존명사/후치 표현` as a flexible semantic chunk, not an absolute no-split rule. Example preferred split: `소프트웨어나 이런 것 쪽으로 많이 다뤘었는데` as one cue when within max length. But this is context-dependent: split only if a different boundary improves meaning closure, rhythm, or max-length compliance.
- Product-name spelling in Korean spoken subtitles should match the Korean caption style unless the user asks otherwise: `재미나이/재미나/Gemini` → `제미나이`, not English `Gemini`.

The quality score is primarily determined by three axes, and subagents must be briefed on these explicitly:

1. **Text correction quality** — spelling/spacing, ASR errors, proper nouns, numbers, units, company/person names, and no invented meaning.
2. **Readable caption segmentation** — natural spoken rhythm, short cue bodies, semantic line breaks, no ugly splits, no orphan particles/endings, good handling of lists, fillers, `그다음에/그러니까/근데/뭐 이런` transitions, and TTimes-style visual readability.
3. **Cue timing quality** — cue starts/ends matched to speech, no overlaps, no long holds, no sub-second flashes unless intentional, refinement from word timestamps.

Safe default roles:

- Main Hermes: source download, ASR, transcript/caption substrate prep, final script integration, final SRT generation/refinement/validation, and delivery.
- Subagent A: term/proper-noun/number correction review. Return proposed corrections with evidence and line/time references.
- Subagent B: line-length/readability/segmentation review. Return line-level rewrite/split suggestions, especially long or awkward cues.
- Subagent C: omission/distortion review comparing YouTube captions + MLX ASR to the script draft. Flag missing meaning, hallucinations, or over-polishing.

For videos over ~20 minutes, split into time/paragraph chunks and use subagents on chunks. For 40–50+ minute dialogue videos, use at least term-correction and readability reviews, and usually omission/distortion review too. For delivery candidates around 1,500–2,000+ cues, do not ask one reviewer to inspect an unbounded full program under a short timeout. Split segmentation review into contiguous responsibilities of roughly 900–1,000 cues and split source/term/number review into contiguous windows of at most about 30 minutes. Every partition must inspect the same immutable full-candidate hash; include each seam in both neighboring briefs or assign it explicitly. If concurrency limits require multiple batches, do not edit the body between batches—they remain one review generation. Keep broad web research out of the timed source audit; provide local captions, glossary, ledger, targeted clips, and exact audio, then let Main handle unresolved external verification. Integrate reports only after every partition has returned, and read the saved reports rather than trusting headline summaries. See `references/long-form-subagent-partitioning-and-scope-gates.md`.

At the early stage of this workflow, because Hermes/subagents are still calibrating the user's preferred segmentation style, run the work like a short peer-review meeting: have subagents inspect chunks using the human-readability frame — **짧게 자르지 말고, 의미가 닫히는 지점에서 자른다** — then compare disagreements before Main Hermes normalizes one style. Peer review should explicitly score/flag: text correction, meaning-complete cue boundaries, protected phrase preservation, visual rhythm, cue timing, and ambiguous particle choices (`에` vs `의`, especially `AI에`/`AI의`). If the reviewers disagree on a recurring rule, or if a segmentation choice requires the user's editorial taste, pause and ask/call the user for guidance rather than guessing. Treat the user's feedback as evolving style law and patch this skill when a new rule is approved. If subagent results arrive after an initial delivery, still integrate high-confidence fixes, rerun alignment/validation from the final script, and resend the updated SRT. It is acceptable if this takes longer; quality is more important than speed.

**Approved-sample fidelity gate:** before showing the 0–3 minute sample, run three separate reviews: (1) cue-by-cue source fidelity against ASR/audio, (2) every-adjacent-boundary segmentation, and (3) proper-noun/technical-term/number verification. A readability reviewer may propose cleaner paraphrases that silently remove repetitions, connectors, particles, self-corrections, or scope words such as `같은 데`; do not accept those automatically. **Reviewer authority is role-bounded:** segmentation review is token-preserving by default and may redesign boundaries/punctuation, but it may not add implied verbs, replace nouns, remove repetition, or strengthen wording. Any lexical rewrite must pass the source-fidelity gate with direct evidence and be recorded in the correction ledger. When readability conflicts with fidelity, preserve the spoken wording and redesign only the protected phrase boundary. Distinguish factual slips from ASR errors: if targeted clip ASR confirms the speaker actually said a factually suspect term, preserve the speech; correct only clear recognition/terminology errors, and record `from/to/basis` in a correction ledger. Detailed arbitration examples and stale-review handling: `references/2026-07-youtube-plan-routing-and-dual-asr-sample.md`. See also `references/2026-07-13-technical-dialogue-sample-fidelity-and-ledger.md`.

**Approved-sample freeze:** once the user approves the 0–3 minute sample, freeze its exact non-empty lines and hash. Preserve it as an exact prefix of the full body; assert prefix equality before every final alignment. Later global cleanup, old-body reuse, and automated merging must not rewrite approved sample cues. Record line count, hash, and any user-approved protected-phrase length exception in a manifest. A later direct factual correction from the user (for example, a speaker's proper-name spelling) is the only normal reason to patch the frozen sample, and that correction must propagate through all derived artifacts. See `references/2026-07-10-approved-sample-name-ledger-length-exception.md` and `references/2026-07-13-technical-dialogue-sample-fidelity-and-ledger.md`.

Never trust subagent self-reports for final files. Main Hermes must integrate edits, read/validate final script/SRT itself, and run cue matching/refinement from the beginning after major segmentation changes. Do not directly extract subagent `cue 후보` blocks as the final script; they are review material, not an aligned transcript. If a rebuild lowers timing/text alignment badly (e.g. avg match drops or low-match count rises), stop and fix instead of delivering. Read spot-check ranges in the final SRT before delivery, especially after automated remerge.

If a plan or brief makes subagent review mandatory and subagents are dispatched in the background, do **not** mark the review task complete or imply their findings were integrated until their summaries actually return. Either wait and integrate high-confidence findings, or explicitly label the delivery as `Main 검증 선납품본` and state that a later patched version may follow. Never silently convert an unfinished subagent review into a completed checklist item.

**Reviewer freshness rule:** reviewers must inspect the revision intended for delivery. Record the candidate body hash/counts in their brief. If Main substantially rewrites or compresses the body after dispatch, their line numbers and omission conclusions are stale; search quoted phrases for still-relevant findings and re-run at least omission/distortion review on the current candidate before freeze. Never claim “3-way review integrated” solely from reviews of an earlier draft. See `references/body-first-normalization-and-stale-review-guard.md`.

**Immutable reviewer snapshot rule:** never dispatch reviewers against the live working-body path that Main may continue patching. First copy the candidate to a content-addressed snapshot such as `review/candidate_<sha256>.txt`, verify its line count/hash, and give reviewers only that immutable path. Every returned finding is explicitly labeled as belonging to that snapshot hash. When integrating into a newer body, treat line numbers as stale and exact-search each quoted current string.

**Review convergence rule:** immutable paths alone are not enough. Finish the Main-known body edits before dispatching a final review generation, then **do not edit the working body while those reviewers run**. Editing during review guarantees a stale result and can trigger an endless freeze→patch→review loop. Use at most two normal generations: (A) independent source/segmentation/term review of the Main-complete candidate; (B) one fresh combined verifier after integrating A. A third generation is warranted only when B's fixes materially change meaning/source coverage, a partition was never reviewed, or prior review was not actually exhaustive. Do not keep requesting “one more fresh review” for tiny deterministic fixes.

For segmentation convergence, distinguish **blocking defects** from **optional packing**. Blocking defects—protected-phrase splits, orphan fragments, packed question/answer beats, misleading quote/predicate attachment, overlength, or source-order loss—must reach zero. A pair is not a failure merely because two independently readable cues could also be merged under 27 characters. Adjacent-fit enumeration generates candidates; it is not a zero-tolerance lint. After a full all-boundary generation and token-preserving fixes, recheck changed windows plus outer seams and deterministic whole-body audits instead of reopening untouched regions as a new aesthetic search. Freeze when source/term findings and blocking segmentation findings are zero; record equally valid rhythm alternatives as non-findings. See `references/finite-segmentation-convergence-and-severity.md`.

Integrate each generation once, in a single adjudicated batch. Resolve reviewer conflicts before editing, then generalize confirmed error classes and rerun deterministic audits.

**Authoritative-line baseline and no-global-reoptimization rule:** when a trusted user/Gemini transcript already supplies readable non-empty lines, use those line boundaries as the conservative starting baseline. Split only overlength lines first; do not flatten the whole transcript and globally repack or merge trusted rows merely to equalize cue lengths. Reviewers may move boundaries across adjacent rows only for a concrete grammatical/semantic defect. Apply approved findings as exact local replacements on one immutable candidate. After any all-cue review, never run a global optimizer that can create unreviewed boundaries. If a local fix changes seams, recheck that changed window and its outer seams; do not reopen untouched ranges as a new aesthetic search. Reviewer proposals are hypotheses: reject or revise any proposal that repairs one split by creating another, makes a needless short tail, exceeds the visible-length box, or miscopies the current cue. Freeze only the exact post-adjudication body that was itself reviewed and mechanically revalidated.

**Partitioned convergence + semantic timing repair:** when a 40–60 minute reviewer risks timeout, split source/term review by timestamp and segmentation review by cue range, but keep every partition on the same immutable hash and include seams on both sides. In repeat segmentation prompts, forbid findings based only on “these cues also fit under 27 characters”; count actual protected-phrase splits, orphan fragments, question/answer packing, and broken quotations. After body freeze, compare aligners by ASR word-midpoint coverage and spoken-gap thresholds. Corrected English terms may appear as unmatched Korean ASR transliterations; attach each gap to the semantically owning left or right cue, never a blind midpoint. Preserve genuine short replies and apply timing-only minimum-duration repair only to manually selected non-standalone cues. Detailed procedure: `references/2026-07-23-long-interview-scope-review-semantic-timing.md`.

Reviewer authority is role-bounded:

- source reviewer may demand lexical restoration/removal only with direct cut-audio/ASR and approved-transcript evidence;
- segmentation reviewer is token-preserving by default and owns boundaries/punctuation, not paraphrase;
- term reviewer owns verified spelling/case/numbers, but must not force unspoken English parentheticals or glossary expansions when they break the 27-character box or a protected phrase.

**Patch-scope and async completion gate:** when deleting or repartitioning cues, patch only the exact intended cue(s), then immediately re-read neighboring cues and rerun the normalized source/body diff; never replace a broad context block with empty text. A background reviewer is unfinished until its report/result returns and Main reads and adjudicates it. Do not mark review complete, rename the artifact as final, or deliver it while the required latest-hash reviewer is still running. Dispatch success is not review completion.

Conflict hierarchy: **actual cut audio → approved cut transcript → correction ledger/verified official term → minimal readable-Korean correction → reviewer preference**. A cleaner paraphrase is not automatically a correction.

When source fidelity and readable grammar conflict, Main must adjudicate the exact span **once** in the correction ledger (`source wording / chosen subtitle wording / evidence / reason`). Typical case: the speaker really uttered an ungrammatical particle chain, while a source reviewer demands exact restoration and a grammar reviewer demands repair. Choose the least meaning-changing readable form under the hierarchy, record it, and instruct later reviewers to treat that ledger decision as fixed. Do not oscillate between the two variants across review generations merely because different reviewers optimize different axes.

If an async review arrives after a newer body or after delivery, never act from its headline count alone. Read the full report, exact-search every quoted `current string` in the actual latest body, discard findings whose strings no longer exist, and integrate all surviving findings in **one batch**. Then regenerate alignment and run the complete validator once. Do not send a chain of “final” attachments for each late stale report; if delivery happened prematurely, wait for all already-dispatched reviewers, consolidate once, and send one clearly labeled replacement. See `references/2026-07-21-review-convergence-and-freeze-discipline.md` for the finite review protocol, exact-string integration, patch-scope safeguards, async completion gate, and punctuation-lint cautions.

**Alignment-call budget:** while the body is mutable, run at most one diagnostic alignment when timing can reveal missing spoken words or sub-0.7-second segmentation failures. Run the full alignment/coverage/repair cycle only after the delivery candidate is frozen. Do not remap every intermediate patch generation. For each ASR gap, first distinguish `word absent from body` (source/grammar decision) from `word present but outside cue interval` (timing-only repair); timing cannot repair deleted text.
