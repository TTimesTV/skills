# 장편 인터뷰 말자막: MLX 청크 전사·본문 동결·타임코드 정렬

## 적용 범위

30~60분 한국어 인터뷰에서 공식 자막이 없고, 원발화 밀착형 티타임즈 말자막을 만드는 경우.

## 검증된 순서

1. 원본 오디오 길이를 `ffprobe`로 확인하고 5분 청크로 분할한다.
2. MLX Whisper로 모든 청크에 `word_timestamps=True`를 적용한다.
3. 첫 3분은 Turbo/Large-v3를 대조해 타임코드 없는 샘플을 만들고, 원문·분절·용어 3축 리뷰 후 사용자 승인을 받는다.
4. 승인 샘플은 별도 파일과 SHA-256으로 동결한다. 전체 본문의 prefix가 승인본과 exact match인지 매 단계 검사한다.
5. 나머지 구간은 2~3개 범위로 나눠 초벌을 병렬 작성하되, Main이 청크 경계 문장과 용어를 통합한다.
6. 전체 후보를 다시 원문 충실도·모든 인접 cue 경계·고유명사/숫자 3축으로 전수 리뷰한다.
7. 본문을 최종 동결한 뒤에만 단어 타임스탬프를 배치한다. 본문 수정과 타이밍 수정 단계를 섞지 않는다.
8. SRT 형식 TXT를 생성한 뒤 본문 exact match, 시간 순서, 겹침, 0초 cue, 장기 잔류, 발화 포함 공백을 검증한다.

## ASR 환각 복구

- 전체 병합 전에 각 청크의 시작·끝 세그먼트와 동일문장 반복을 검사한다.
- 10~30초 동일 토큰 반복이나 공백이 발견되면 해당 구간만 원본에서 다시 잘라 Large-v3로 재전사한다.
- 복구 JSON의 세그먼트·단어 타임스탬프에 전역 오프셋을 더한 뒤, 겹치는 기존 세그먼트와 단어를 교체한다.
- 복구 전사를 만든 뒤 병렬 초벌 작업자가 이미 손상본을 사용했을 수 있으므로 Main이 해당 범위 본문을 반드시 다시 채운다.

## 장편 정렬기 선택

동일 본문에 두 정렬기를 진단 실행해 수치로 선택한다.

- `align_lines_to_chunked_words.py`: 문자 기반·최대 노출시간 제한이 강해 핵심 단어만 잡고 발화 중 공백을 많이 만들 수 있다.
- `align_user_lines_to_whisper_json.py`: 토큰 기반이며 장편에서도 본문 순서를 보존하면서 단어 커버리지가 더 높을 수 있다.

2026-07-20 사례:

- 문자 기반: 본문 exact, char ratio 0.976이었지만 단어 중간점 커버리지 69.5%, 발화 포함 공백 683곳.
- 토큰 기반: 본문 exact, sequence ratio 0.932~0.936, 단어 중간점 커버리지 99.66%.

따라서 ratio 하나만 보지 말고 **단어 커버리지와 발화 포함 공백 수**까지 비교한다.

## 발화 포함 공백 보정

- 인접 cue 사이 0.25초 이상 공백에 MLX 단어가 실제 존재하는지 검사한다.
- 본문 순서가 승인본 때문에 음성 어순과 조금 다른 경우, 본문을 재작성하지 말고 앞 cue의 종료를 다음 cue 시작 40ms 전까지 연장해 단어를 덮는다.
- 실제 단어가 없는 무음은 유지한다.
- 보정 후 겹침 0, 비양수 길이 0, 발화 포함 공백 0을 다시 확인한다.

## 리뷰 동시성 주의

**리뷰가 진행 중인 파일을 in-place로 패치하지 않는다.** 리뷰 대상 파일을 해시로 동결하고, Main 수정은 새 버전에만 쓴다. 그렇지 않으면 reviewer 줄 번호와 해시가 중간에 달라져 결과 통합이 불안정해진다.

권장 버전 흐름:

`candidate_v1_review_frozen.txt` → 리뷰 완료 → `candidate_v2_integrated.txt` → 최종 동결

## 최종 품질 게이트

- 승인 샘플 prefix exact match
- cue 본문 줄 수 = SRT cue 수
- cue 번호 연속
- 최대 27자(예외는 수동 승인)
- cue 끝 마침표 0
- 시간 역전·겹침·0초 cue 0
- 5.5초 초과 cue 0 또는 전수 수동 판정
- 발화 단어 중간점 커버리지 99% 이상
- ASR 단어가 존재하는 cue 사이 공백 0
- 마지막 cue가 마지막 발화까지 도달
- 최종 파일 SHA-256과 manifest 기록
