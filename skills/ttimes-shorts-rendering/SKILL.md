# TTimes Shorts Rendering

## 목적

이미 편집과 승인이 끝난 TTimes 16:9 하이라이트를 **교양이를 부탁해형 1080×1920 쇼츠 셸**에 넣어 실제 MP4로 렌더링한다.

이 스킬이 자동화하는 범위는 다음과 같다.

```text
승인된 16:9 하이라이트
→ 승인된 상단 제목·화자명 적용
→ TTimes 세로 셸 합성
→ 실제 TTimes 로고·구독&좋아요 CTA 적용
→ MP4 렌더
→ 접촉시트·코덱·디코딩 QA
→ 파일 전달
```

이 스킬만으로 하이라이트를 새로 선정하거나 발언을 재배열하지 않는다. 원본 장편에서 쇼츠 구간을 고르는 일은 편집 판단이며, 먼저 `ttimes-cut-editing` 또는 사용자의 명시적 승인을 거쳐야 한다.

## 사용할 때

- 사용자가 `저번처럼 티타임즈 쇼츠 만들어`, `키미 K3 때 그 레이아웃`, `교양이를 부탁해형 쇼츠`라고 요청할 때
- 완성된 16:9 하이라이트를 세로 쇼츠로 감쌀 때
- TTimes 제목·로고·CTA가 포함된 반복 가능한 세로 템플릿을 렌더할 때

다음에는 사용하지 않는다.

- 원본 장편에서 쇼츠 후보를 자율 선정해야 할 때
- 기존 하이라이트의 컷·자막·자료화면을 다시 편집해야 할 때
- 사용자가 다른 레퍼런스나 새 디자인을 명시했을 때
- TTimes가 아닌 브랜드의 쇼츠를 만들 때

## 승인된 기준 산출물

현재 기준 사례:

```text
프로젝트: PROJECT_ROOT/2TdSkEyIUrI
최종본: output/260731_키미 K3 티타임즈 쇼츠 최종 레이아웃.mp4
오버레이: work/title_overlay_ttimes_cta_final.png
오버레이 생성기: PROJECT_ROOT/create_ttimes_cta_final_overlay.py
공식 로고: assets/ttimes_logo_red_white.png
최종 접촉시트: reports/contact_sheet_ttimes_cta_final.jpg
```

검증된 최종본의 기술 정보:

```text
1080×1920
42.28초
30fps
H.264 / yuv420p
AAC
디코딩 오류 0건
SHA-256: 0ee78a052565447a472ac8dde8227fb23eae825b1e25bb4fc23623dc6ae80c7f
```

이 값들은 Kimi K3 기준 사례다. 새 영상의 길이와 해시는 새 산출물에서 다시 측정해야 한다.

## 고정 디자인 계약

사용자가 새 디자인을 요청하지 않는 한 다음을 유지한다.

### 캔버스와 중앙 영상

```yaml
canvas: [1080, 1920]
video_box: [0, 500, 1080, 608]
aspect_ratio: 16:9
placement: contain
crop: prohibited
source_burned_captions: preserve
source_audio: preserve
```

- 16:9 하이라이트를 `1080×608`로 비율 유지 확대한다.
- 세로 얼굴 추적 크롭을 하지 않는다.
- 기존 하이라이트의 자막·그래픽·B-roll·오디오를 그대로 보존한다.
- 영상 창 위·아래에 흰색 찢어진 종이 경계선을 유지한다.
- 오버레이 PNG의 실질 투명 창은 경계선 때문에 대략 `y=514–1098`이지만, 합성 영상의 기준 박스는 `y=500, h=608`이다.

### 상단

- 배경은 파란 신문·종이 질감이다.
- 상단에 별도 TTimes 로고를 넣지 않는다.
- 메인 제목은 **Gmarket Sans Bold**를 사용한다.
- 제목은 2행을 기본으로 하되 승인된 줄바꿈을 그대로 쓴다.
- 기준 위치는 1행 중심 `y≈225`, 2행 중심 `y≈355`, 화자명 `y≈445`다.
- 화자명은 본문보다 작고 옅은 색으로 둔다.
- 제목은 원본 발언·승인된 기획 문구를 근거로 하며, 클릭을 위해 수치·인과·확정성을 강화하지 않는다.

### 하단

- 실제 TTimes 워드마크를 중앙에 배치한다.
- 기준 로고 박스는 최대 `500×147`, 상단 `y≈1168`이다.
- 네온초록 타원형 `구독 & 좋아요` CTA는 로고 아래에서 **왼쪽으로 치우쳐** 배치한다.
- 기준 CTA 박스는 `(145,1328)–(775,1503)`이다.
- CTA 문구는 Gmarket Sans Bold, 검정 계열로 유지한다.
- 하단 여백을 억지 장식이나 추가 문구로 채우지 않는다.

### YouTube UI 제외

다음은 YouTube 앱이 자동으로 표시하므로 MP4에 굽지 않는다.

- `@TTimesTV`
- 채널 아바타
- `가입` 버튼
- 좋아요·댓글·공유 우측 레일
- 재생·볼륨·CC·설정·진행 바

검수용 UI 목업은 만들 수 있지만 최종 MP4에는 포함하지 않는다.

## 작업 순서

### 1. 입력과 승인 상태 확인

반드시 확인한다.

- 입력 파일이 편집 완료된 16:9 하이라이트인지
- 하이라이트 구간과 마지막 음절이 승인됐는지
- 상단 제목과 화자명이 승인 문구인지
- 실제 TTimes 로고 파일이 읽히는지
- 출력 경로와 파일명이 정해졌는지

완료 기준: 입력 영상, 제목, 화자명, 로고, 출력 경로가 모두 특정돼 있다.

### 2. 원본 하이라이트 경계 검수

- 시작·종료 전후 프레임과 오디오를 확인한다.
- 다음 본편 인트로나 관련 없는 프레임이 유입되지 않게 한다.
- 마지막 발화보다 화면이 먼저 바뀌면 마지막 정상 프레임을 짧게 고정하고 원래 오디오는 자연스러운 끝까지 보존한다.
- Kimi K3 사례에서는 마지막 정상 화면을 고정해 다음 진행자 인트로 유입 없이 마지막 음절을 살렸다.

완료 기준: 시작 누출, 다음 장면 누출, 마지막 음절 절단이 없다.

### 3. 정적 오버레이 생성

사용자 Mac에서는 아래 생성기를 기준으로 복사해 새 프로젝트에 맞게 경로와 문구만 바꾼다.

```text
PROJECT_ROOT/create_ttimes_cta_final_overlay.py
```

바꿔야 하는 값:

- `OUT`
- `LOGO`
- 제목 1·2행
- 화자명

유지할 값:

- `W,H=1080,1920`
- `VIDEO_Y,VIDEO_H=500,608`
- Gmarket Sans Bold 제목
- 파란 종이 질감과 고정 random seed
- 실제 TTimes 중앙 로고
- 왼쪽 네온초록 CTA

오버레이 생성 후 PNG 크기와 alpha를 검사한다.

```bash
python3 - <<'PY'
from PIL import Image
p='OVERLAY.png'
im=Image.open(p).convert('RGBA')
assert im.size == (1080,1920)
assert im.getchannel('A').getextrema() == (0,255)
print('PASS', im.size, im.getchannel('A').getextrema())
PY
```

완료 기준: 1080×1920 RGBA PNG이며 중앙 영상 창이 투명하다.

### 4. 정적 미리보기 승인

전체 MP4보다 먼저 대표 프레임 1장에 오버레이를 합성해 확인한다.

- 제목 오탈자·줄바꿈·잘림
- Gmarket Sans Bold 적용
- 화자명
- 영상 창 위치와 16:9 비율
- 기존 번인 자막 가독성
- 실제 TTimes 로고 비율과 중앙 정렬
- CTA의 왼쪽 배치
- YouTube UI 미포함

사용자가 제목이나 배치를 아직 승인하지 않았다면 이 단계에서 멈춘다. 승인 전 전체 MP4를 반복 렌더하지 않는다.

완료 기준: 정적 프리뷰의 제목·폰트·레이아웃이 승인됐다.

### 5. MP4 합성

아래 명령은 기존 `highlight.mp4`와 승인된 RGBA 오버레이를 합성하는 검증된 기본형이다.

```bash
ffmpeg -y -i 'highlight.mp4' -loop 1 -framerate 30 -i 'overlay.png' \
-filter_complex "color=c=black:s=1080x1920:r=30[bg];[0:v]scale=1080:608:flags=lanczos[hv];[bg][hv]overlay=0:500:shortest=1[stage];[stage][1:v]overlay=0:0:format=auto[outv]" \
-map '[outv]' -map 0:a:0 \
-c:v libx264 -pix_fmt yuv420p -r 30 \
-c:a aac -b:a 192k -movflags +faststart -shortest \
'final.mp4'
```

입력에 오디오가 없으면 무음이라고 보고하지 말고, 사용자에게 확인하거나 명시적으로 무음 출력 분기로 처리한다.

완료 기준: 실제 1080×1920 MP4가 생성되고 원본 오디오가 들린다.

### 6. 기술 QA

```bash
ffprobe -v error \
-show_entries stream=codec_name,codec_type,width,height,pix_fmt,r_frame_rate \
-show_entries format=duration,size -of json 'final.mp4'

ffmpeg -v error -i 'final.mp4' -f null -

shasum -a 256 'final.mp4'
```

통과 조건:

- 1080×1920
- H.264
- yuv420p
- 30fps
- AAC 오디오 존재
- 기대한 길이
- 전체 디코딩 exit 0, 오류 출력 없음
- SHA-256 기록

### 7. 시각 QA

3–4초 간격 접촉시트와 시작·중간·끝 프레임을 만든다. 최소 확인 항목:

- 상단 제목 전 구간 고정·무잘림
- 영상이 `y=500`에서 16:9로 유지
- 얼굴·자료화면·기존 자막 왜곡 없음
- 영상이 투명 창 밖으로 새지 않음
- 찢어진 경계선이 기존 자막을 가리지 않음
- 실제 TTimes 로고가 중앙에 유지
- CTA가 로고 아래 왼쪽에 유지
- YouTube 네이티브 UI가 없음
- 검은 프레임·다음 장면 누출·잔상 없음

대표 접촉시트 생성기는 다음 경로에 있다.

```text
PROJECT_ROOT/make_contact_sheet.py
```

완료 기준: 기술 QA와 시각 QA가 모두 PASS다.

- 날짜와 내용을 알아볼 수 있는 한국어 파일명을 쓴다.
- 실제 MP4를 `MEDIA:/absolute/path/file.mp4`로 전달한다.
- 경로만 알려주고 전달 완료라고 하지 않는다.

## 정본·재인코딩·부분 수정 관리

- **텔레그램 회수본을 정본으로 삼지 않는다.** Telegram이 영상으로 전송한 파일은 플랫폼 처리·재압축 가능성이 있다. 수정 요청을 받으면 먼저 프로젝트의 로컬 마스터와 빌드 스크립트를 찾아 원본 레이어에서 재렌더한다. 로컬 정본이 없을 때만 회수본을 사용하고 그 사실을 밝힌다.
- **완성 MP4 위에 반복 후처리하지 않는다.** 자막 제거, 로고, 화면비, BGM 수정이 누적될수록 H.264 세대손실과 링잉이 커진다. 가능한 한 원본 자료영상·자막 PNG/SRT·내레이션·BGM에서 한 번에 합성한다.
- **마스터와 전달본을 분리한다.** 고품질 마스터를 보존하고 Telegram 크기 제한용 전달본을 별도로 만든다. 전달본이 정본을 덮어쓰지 않게 하며, 둘의 길이·프레임 수·오디오·대표 프레임을 비교한다.
- **부분 수정은 영향 범위를 고정한다.** 사용자가 한 구간만 고치라고 하면 그 구간 외 픽셀·오디오가 바뀌지 않았는지 프레임/스트림 해시 또는 대표 구간 비교로 검증한다. 변경 요청을 계기로 자막 문구·장면·로고·오디오를 임의 재최적화하지 않는다.
- **렌더 전 미확보 레이어를 명시한다.** 원본 영상, 권위 SRT, 로고, BGM, 내레이션 중 빠진 자산을 이전본에서 묵시적으로 유지하지 말고 어떤 기준본을 재사용하는지 기록한다.

## 원본 번인 말자막 정밀 제거 — 사용자 요청 시에만

기본값은 `source_burned_captions: preserve`다. 다만 사용자가 원본 자료영상 내부의 영문 말자막 제거를 명시적으로 요청하면, 하단 전체에 큰 `delogo` 사각형을 적용하지 않는다. 2026-08-05 zHBM 쇼츠에서 검증된 방식은 다음과 같다.

1. **시간과 공간을 함께 분할한다.** 0.125초 간격 하단 ROI 접촉시트로 문장별 IN/OUT, 장면 전환, 크로스페이드에서 이전 자막이 남는 마지막 프레임까지 찾는다.
2. **문장·행마다 별도 마스크를 쓴다.** 2행 자막과 1행 자막을 각각 실제 글자 폭·높이만 포함하는 좁은 마스크로 처리한다. 하나의 전역 하단 띠로 퉁치지 않는다.
3. **글자는 국소 인페인트한다.** OpenCV `INPAINT_TELEA` 등의 작은 반경으로 실제 글자 박스만 주변 픽셀로 복원한다. 마스크 경계에 안티앨리어싱 획이 남지 않도록 대표 프레임뿐 아니라 전환 프레임까지 검사하고 필요한 만큼만 확장한다.
4. **반투명 배경 바는 별도로 복원한다.** 자막 렌더러가 균일한 검정 알파 바를 깔았다면 전체를 블러하지 말고 측정한 높이와 알파에 한해 `original ≈ composited / (1-alpha)`로 역산한다. zHBM 사례는 최종 1080×1920 캔버스의 `y=1163:1210`, 약 35% 검정 바였고, `pixel/0.65` 복원으로 배경 선과 질감을 보존했다. 이 좌표·알파는 다른 영상에 재사용하지 말고 매번 측정한다.
5. **캔버스 배경 블러와 본화면 내부 블러를 구분한다.** 세로 캔버스 위아래의 동일 영상 기반 블러 배경은 유지할 수 있지만, 중앙 16:9 본화면 내부에는 사용자가 금지한 넓은 번짐 띠를 만들지 않는다.
6. **오디오는 비트 단위로 보존한다.** 화면만 수정하는 작업은 기존 AAC를 `-c:a copy`로 유지하고 입력·출력 오디오 스트림 SHA-256 일치를 확인한다.
7. **필수 QA:** 처리 구간 0.125초 ROI 접촉시트, 장면 경계 프레임 전수 시트, 전체 2–4초 접촉시트, 전체 디코딩, 코덱·길이·파일 크기·해시를 확인한다. 영문 획 잔재, 반투명 바, 마스크 전환 튐, 직사각 패치, 검정/회색 빈 프레임이 하나라도 보이면 완료하지 않는다.

## 실패 방지 규칙

1. **완성 하이라이트 재편집 금지:** 세로 셸 작업 중 기존 컷·자막·B-roll을 임의 변경하지 않는다.
2. **세로 크롭 금지:** 얼굴을 크게 보이게 하려고 16:9 프레임을 잘라내지 않는다.
3. **제목 과장 금지:** 원문보다 센 인과·수치·확정 표현을 만들지 않는다.
4. **상단 로고 금지:** 승인된 TTimes 쇼츠는 상단 무로고다.
5. **가짜 UI 금지:** `@TTimesTV`, `가입`, 우측 반응 버튼을 영상에 굽지 않는다.
6. **가짜 로고 금지:** 텍스트로 TTimes를 흉내 내지 말고 실제 로고 자산을 쓴다.
7. **CTA 중앙 회귀 금지:** 네온초록 CTA는 하단 중앙이 아니라 로고 아래에서 왼쪽으로 이동된 승인 배치를 유지한다.
8. **프리뷰 생략 금지:** 제목·폰트 승인 전에 전체 MP4를 렌더하지 않는다.
9. **기술 QA만으로 완료 금지:** ffprobe가 통과해도 접촉시트를 보지 않았다면 완료가 아니다.
10. **샘플 경로 하드코딩 금지:** 새 프로젝트에서는 출력·로고·문구 경로를 새 프로젝트로 바꾼다.
